# 빅데이터 분석 기획 (빅데이터의 이해)

> 필기 1과목 앞부분. 출제기준(2024.1.1~2026.12.31)의 주요항목 빅데이터의 이해(개요 및 활용, 기술 및 제도)를 다룬다. 분석 계획과 수집, 저장은 01b 파일에 있다.
> 법 조문은 국가법령정보센터의 현행 개인정보 보호법(법률 제21445호, 2026.9.11 시행), 신용정보법, 정보통신망법으로 확인했다.

## 빅데이터의 특징

- **규모 (Volume)** — 저장하고 처리해야 할 데이터의 양이 기존 도구로 다루기 어려울 만큼 크다는 특성
- **다양성 (Variety)** — 정형뿐 아니라 텍스트, 로그, 이미지, 영상처럼 형태가 서로 다른 데이터가 섞여 있다는 특성
- **속도 (Velocity)** — 데이터가 빠르게 생성되고, 수집과 처리, 분석도 실시간에 가깝게 이루어져야 한다는 특성
- **정확성 (Veracity)** — 데이터에 섞인 잡음, 편향, 오류 때문에 그 데이터를 얼마나 믿을 수 있는지를 따지는 특성
- **가치 (Value)** — 분석으로 비즈니스나 사회에 쓸모 있는 결과를 끌어낼 수 있어야 한다는 특성
- Q: 빅데이터 3V — Volume, Variety, Velocity
  - 여기에 Veracity를 더하면 4V, Value까지 더하면 5V로 부른다.
- Q: ROI 관점에서 4V를 나눌 때 투자 비용 쪽이 아니라 비즈니스 효과 쪽에 속하는 V — Value
  - Volume, Variety, Velocity는 투자 비용(난이도) 요소로 본다.
- Q: 빅데이터 시대에 분석 관점이 바뀐 방향 네 가지 — 사전처리에서 사후처리로, 표본조사에서 전수조사로, 질보다 양으로, 인과관계에서 상관관계로

## DIKW 피라미드

- Q: DIKW 피라미드를 아래층부터 순서대로 — 데이터 → 정보 → 지식 → 지혜
- Q: "A 마트 볼펜 500원, B 마트 볼펜 700원"처럼 가공하지 않은 개별 사실은 DIKW 중 어느 층 — 데이터
- **정보 (Information)** — 개별 사실을 가공하고 서로 연관 지어 의미를 드러낸 것. 예: 볼펜은 A 마트가 B 마트보다 싸다
- **지식 (Knowledge)** — 의미가 드러난 내용을 구조화하고 자기 상황에 연결해 판단 근거로 삼는 것. 예: 볼펜은 A 마트에서 사겠다
- **지혜 (Wisdom)** — 쌓인 판단 근거에 창의적 통찰을 더해 새로운 상황까지 추론하는 것. 예: A 마트는 다른 문구류도 쌀 것이다

## 데이터의 유형과 지식의 형태

- **정형 데이터 (Structured Data)** — 미리 정한 스키마에 맞춰 행과 열로 저장되어 곧바로 집계와 연산을 할 수 있는 데이터. 예: RDB 테이블, CSV
- **반정형 데이터 (Semi-structured Data)** — 고정된 테이블은 아니지만 태그나 키 같은 메타데이터가 값과 함께 들어 있어 구조를 읽어 낼 수 있는 데이터. 예: JSON, XML, HTML, 로그
- **비정형 데이터 (Unstructured Data)** — 정해진 구조가 없어 바로 연산하기 어렵고 전처리로 특징을 뽑아야 하는 데이터. 예: 자유 텍스트, 이미지, 영상, 음성
- Q: JSON 문서와 웹 서버 로그는 정형, 반정형, 비정형 중 — 반정형
- Q: 콜센터 통화 녹음 파일은 정형, 반정형, 비정형 중 — 비정형
- **정량적 데이터 (Quantitative Data)** — 수치로 측정되어 크기 비교와 연산이 가능한 데이터. 저장과 검색, 분석이 쉽다
- **정성적 데이터 (Qualitative Data)** — 글이나 범주로 표현된 서술형 데이터. 형태가 일정하지 않아 저장과 분석에 비용이 더 든다
- **암묵지 (Tacit Knowledge)** — 개인의 경험과 몸에 배어 있어 문서나 말로 옮기기 어려운 지식. 예: 숙련공의 감
- **형식지 (Explicit Knowledge)** — 문서, 매뉴얼, 데이터베이스처럼 형태를 갖춰 다른 사람과 공유할 수 있는 지식
- Q: 노나카의 지식 창조(SECI) 순환 네 단계 — 공통화(Socialization) → 표출화(Externalization) → 연결화(Combination) → 내면화(Internalization)
  - 암묵지가 형식지로 바뀌는 단계가 표출화, 형식지가 다시 개인의 암묵지로 흡수되는 단계가 내면화다.

## 데이터베이스와 저장 구조

- Q: 데이터베이스의 일반적 특징 네 가지 — 통합된 데이터, 저장된 데이터, 공용 데이터, 변화하는 데이터
- **데이터 웨어하우스 (Data Warehouse)** — 여러 운영 시스템의 데이터를 의사결정 지원용으로 정제, 통합해 쌓아 두는 중앙 저장소. 적재 전에 스키마를 정한다
  - 특징 네 가지: 주제 지향, 통합, 시계열(시간 변동), 비휘발성
- Q: 데이터 웨어하우스의 비휘발성이 뜻하는 것 — 한번 적재된 데이터는 갱신, 삭제 없이 읽기 위주로 쓰인다
- **데이터 마트 (Data Mart)** — 특정 부서나 주제 분석에 필요한 부분만 떼어 만든 소규모 분석용 저장소
- **데이터 레이크 (Data Lake)** — 정형, 반정형, 비정형 데이터를 원본 형태 그대로 대량 저장해 두고 읽을 때 스키마를 적용하는 저장소
- Q: 적재 시점에 스키마를 정하는 쪽(Schema-on-Write)과 읽는 시점에 정하는 쪽(Schema-on-Read) — 데이터 웨어하우스가 Schema-on-Write, 데이터 레이크가 Schema-on-Read
- **OLTP (Online Transaction Processing)** — 주문, 이체처럼 짧은 트랜잭션을 실시간으로 대량 처리하는 운영계 시스템. 정규화된 현재 데이터를 다룬다
- **OLAP (Online Analytical Processing)** — 이력 데이터를 다차원으로 집계하고 분석하는 분석계 처리. 드릴다운, 롤업, 슬라이스 같은 연산을 쓴다

## 빅데이터의 가치와 위기

- Q: 빅데이터의 가치를 미리 산정하기 어려운 이유 세 가지 — 데이터를 재사용하고 재조합하는 방식이 다양하다, 기존에 없던 가치가 새로 만들어진다, 분석 기술이 계속 발전해 가치가 바뀐다
- Q: 빅데이터의 위기 요인 세 가지 — 사생활 침해, 책임 원칙 훼손, 데이터 오용
- Q: 사생활 침해 위기에 대한 통제 방향 — 개인정보 제공자의 동의에서 사용자의 책임으로 무게를 옮긴다
- Q: 예측만으로 사람을 처벌하는 식의 책임 원칙 훼손에 대한 통제 방향 — 결과 기반 책임 원칙을 고수한다
- **알고리즈미스트 (Algorithmist)** — 알고리즘 때문에 불이익을 받은 사람을 대신해 그 알고리즘을 해석하고 피해를 구제하는 전문가. 데이터 오용 위기의 통제 수단으로 제시된다

## 데이터 산업의 이해

- Q: 데이터 산업이 진화해 온 순서 — 처리 → 통합 → 분석 → 연결 → 권리
  - 마지막 권리 시대는 개인이 자기 데이터의 이동과 활용을 결정하는 마이데이터와 연결된다.
- Q: 신용정보법에서 흔히 마이데이터라 부르는 업의 법률상 명칭 — 본인신용정보관리업
  - 신용정보주체의 신용관리를 돕기 위해 흩어진 신용정보를 통합해 본인에게 제공하는 일을 영업으로 하는 것(신용정보법 제2조 9의2호).
- Q: 데이터 산업 구조를 인프라 영역과 서비스 영역으로 나눌 때 서비스 영역에 속하는 것 — 교육, 컨설팅, 솔루션, 데이터 제공처럼 데이터를 활용하게 돕는 사업
  - 인프라 영역은 하드웨어와 데이터베이스, 플랫폼 같은 기반 소프트웨어다.

## 빅데이터 조직 및 인력

- **집중형 조직 구조 (Centralized Structure)** — 전사 분석 업무를 별도의 전담 조직이 맡아 우선순위를 정하고 수행하는 구조. 현업 부서와 업무가 겹칠 수 있다
- **기능형 조직 구조 (Functional Structure)** — 각 현업 부서가 자기 업무에 필요한 분석을 직접 수행하는 구조. 전사 관점의 핵심 분석이 어렵다
- **분산형 조직 구조 (Distributed Structure)** — 분석 전문 인력을 현업 부서에 배치해 함께 일하게 하는 구조. 전사 차원의 우선순위를 유지하면서 결과를 빠르게 업무에 적용한다
- Q: 데이터 사이언티스트의 하드 스킬과 소프트 스킬 — 하드 스킬은 이론 지식과 분석 기술 숙련, 소프트 스킬은 통찰력, 설득력 있는 전달, 다분야 협업 능력
- Q: 가트너가 꼽은 데이터 사이언티스트의 요구 역량 네 영역 — 데이터 관리, 분석 모델링, 비즈니스 분석, 소프트 스킬
- **CoE (Center of Excellence)** — 기획, 분석, IT 역량을 모아 조직 전체의 분석 역량과 방법론을 이끄는 분석 전문 조직

## 빅데이터 플랫폼

- Q: 빅데이터 플랫폼의 세 계층 — 소프트웨어 계층, 플랫폼 계층, 인프라스트럭처 계층
  - 인프라 계층은 자원 배치와 스토리지, 네트워크를, 플랫폼 계층은 작업 스케줄링과 자원 할당을, 소프트웨어 계층은 수집, 처리, 분석 응용을 맡는다.
- **하둡 (Hadoop)** — 범용 서버 여러 대를 묶어 대용량 데이터를 분산 저장하고 병렬 처리하는 오픈소스 프레임워크
- **HDFS (Hadoop Distributed File System)** — 파일을 블록으로 나눠 여러 노드에 복제 저장하는 하둡의 분산 파일 시스템. 메타데이터는 네임노드, 실제 블록은 데이터노드가 관리한다
  - 하둡 2 이후 기본 블록 크기 128MB, 기본 복제 수 3
- **맵리듀스 (MapReduce)** — 입력을 키-값 쌍으로 나눠 병렬 처리한 뒤 같은 키끼리 모아 집계하는 분산 처리 모델. Map → Shuffle → Reduce 순서로 진행된다
- **YARN (Yet Another Resource Negotiator)** — 하둡 클러스터의 자원 관리와 작업 스케줄링을 맡는 계층. ResourceManager와 NodeManager로 구성된다
- **스파크 (Apache Spark)** — 중간 결과를 디스크 대신 메모리에 두고 처리해 반복 연산이 빠른 분산 처리 엔진. RDD를 기본 자료구조로 쓴다
- **하이브 (Apache Hive)** — 하둡 위의 데이터를 SQL과 비슷한 질의 언어로 조회하게 해 주는 데이터 웨어하우스 도구
- **HBase (Hadoop Database)** — HDFS 위에서 동작하는 컬럼 패밀리 기반의 분산 NoSQL 데이터베이스. 대량 데이터의 실시간 임의 읽기와 쓰기에 쓴다
- **주키퍼 (Apache ZooKeeper)** — 분산 환경의 서버들 사이에서 설정 정보, 이름, 동기화, 리더 선출 같은 조정 작업을 맡는 코디네이션 서비스
- **우지 (Apache Oozie)** — 하둡 작업들을 순서와 조건에 따라 묶어 실행하는 워크플로 스케줄러
- Q: 관계형 DB와 HDFS 사이에서 데이터를 대량으로 주고받는 하둡 생태계 도구 — 스쿱(Sqoop)
- Q: 여러 서버에서 생기는 로그를 모아 HDFS로 보내는 데 쓰는 하둡 생태계 수집 도구 — 플럼(Flume)

## NoSQL과 분산 저장의 원리

- Q: NoSQL 데이터 모델 네 가지와 대표 제품 — 키-값(Redis, DynamoDB), 컬럼 패밀리(HBase, Cassandra), 문서(MongoDB), 그래프(Neo4j)
- **CAP 정리 (CAP Theorem)** — 분산 시스템은 일관성, 가용성, 분할 허용성 세 가지를 동시에 모두 만족할 수 없다는 원리
- **BASE (Basically Available, Soft state, Eventually consistent)** — 엄격한 ACID 대신 가용성을 우선하고 일정 시간이 지나면 일관성이 맞춰지는 것을 허용하는 NoSQL의 트랜잭션 성질
- **스케일 아웃 (Scale-out)** — 서버 대수를 늘려 처리 용량을 키우는 수평 확장 방식. 분산 저장 시스템이 주로 택한다
- **스케일 업 (Scale-up)** — CPU, 메모리 같은 단일 서버의 사양을 올려 처리 용량을 키우는 수직 확장 방식
- **샤딩 (Sharding)** — 하나의 큰 데이터 집합을 키 범위나 해시에 따라 여러 서버로 수평 분할해 저장하는 기법

## 빅데이터와 인공지능

- Q: 인공지능, 머신러닝, 딥러닝의 포함 관계 — 인공지능 ⊃ 머신러닝 ⊃ 딥러닝
- Q: 빅데이터가 인공지능 발전에 기여한 핵심 이유 — 대량의 학습 데이터가 확보되어 복잡한 모델을 학습할 수 있게 됐다
  - 연산 능력(GPU)과 알고리즘 개선이 함께 맞물렸다.

## 개인정보 법과 제도

- Q: 개인정보 보호법상 개인정보의 세 갈래 — 그 자체로 개인을 알아볼 수 있는 정보, 다른 정보와 쉽게 결합해 알아볼 수 있는 정보, 가명정보
  - 모두 살아 있는 개인에 관한 정보다(제2조 제1호 가목, 나목, 다목).
- Q: 다른 정보와 쉽게 결합할 수 있는지를 판단할 때 합리적으로 고려하는 요소 — 다른 정보의 입수 가능성 등 개인을 알아보는 데 드는 시간, 비용, 기술
- **가명처리 (Pseudonymization)** — 개인정보 일부를 삭제하거나 일부 또는 전부를 대체하는 등의 방법으로, 추가 정보 없이는 특정 개인을 알아볼 수 없게 만드는 처리(개인정보 보호법 제2조 제1호의2)
- **가명정보 (Pseudonymous Information)** — 가명처리를 거쳐, 원래 상태로 되돌리는 추가 정보를 쓰거나 결합하지 않으면 특정 개인을 알아볼 수 없게 된 정보. 법상 여전히 개인정보다
- **익명정보 (Anonymous Information)** — 시간, 비용, 기술 등을 합리적으로 고려할 때 다른 정보를 써도 더 이상 개인을 알아볼 수 없는 정보. 개인정보 보호법이 적용되지 않는다(제58조의2)
- Q: 가명정보와 익명정보를 가르는 기준 — 추가 정보를 쓰면 다시 개인을 알아볼 수 있으면 가명정보, 어떤 정보를 더해도 알아볼 수 없으면 익명정보
- Q: 개인정보 보호법이 익명처리와 가명처리 사이에 정한 우선순위 — 익명으로 목적을 달성할 수 있으면 익명처리, 익명으로 안 될 때 가명처리
  - 개인정보 보호 원칙(제3조 제7항).
- Q: 정보주체 동의 없이 가명정보를 처리할 수 있는 목적 세 가지 — 통계작성, 과학적 연구, 공익적 기록보존
  - 개인정보 보호법 제28조의2 제1항. 조문은 이 셋 뒤에 "등"을 붙인다.
- **과학적 연구 (Scientific Research)** — 기술의 개발과 실증, 기초연구, 응용연구, 민간 투자 연구처럼 과학적 방법을 적용하는 연구(개인정보 보호법 제2조 제8호)
- Q: 서로 다른 개인정보처리자의 가명정보를 결합할 수 있는 주체 — 보호위원회나 관계 중앙행정기관의 장이 지정한 전문기관
  - 결합된 정보를 그 기관 밖으로 반출하려면 가명정보나 익명정보로 처리한 뒤 전문기관의 장의 승인을 받는다(제28조의3).
- Q: 가명정보를 처리할 때 원래 상태로 복원하는 추가 정보를 다루는 방법 — 별도로 분리해 보관하고 관리한다
  - 제28조의4 제1항의 안전조치 의무.
- Q: 가명정보 처리 기록을 가명정보를 파기한 뒤 보관해야 하는 기간 — 파기한 날부터 3년 이상
  - 개인정보 보호법 제28조의4 제3항.
- Q: 가명정보 처리 중 특정 개인을 알아볼 수 있는 정보가 생겼을 때 해야 할 일 — 즉시 처리를 중지하고 지체 없이 회수하고 파기한다
  - 제28조의5 제2항. 특정 개인을 알아보려는 목적의 가명정보 처리는 같은 조 제1항이 금지한다.
- Q: 특정 개인을 알아보기 위한 목적으로 가명정보를 처리한 자에 대한 벌칙 — 5년 이하 징역 또는 5천만원 이하 벌금
  - 개인정보 보호법 제71조.
- **민감정보 (Sensitive Information)** — 사상, 신념, 노동조합과 정당의 가입과 탈퇴, 정치적 견해, 건강, 성생활처럼 사생활을 현저히 침해할 우려가 있는 개인정보. 별도 동의나 법령 근거가 있어야 처리한다(제23조)
- **고유식별정보 (Unique Identifying Information)** — 법령에 따라 개인을 고유하게 구별하려고 부여한 식별번호. 처리할 때는 암호화 등 안전성 조치를 해야 한다(제24조)
- Q: 2020년 데이터 3법 개정으로 정보통신망법에서 빠져 개인정보 보호법으로 옮겨 간 것 — 개인정보의 정의와 개인정보 보호 규정
  - 정보통신망법 제2조 제1항 제6호(개인정보 정의)가 2020.2.4. 삭제됐다.
- Q: 데이터 3법 — 개인정보 보호법, 정보통신망법, 신용정보법
- Q: 신용정보법상 익명처리의 정의 — 더 이상 특정 개인인 신용정보주체를 알아볼 수 없도록 개인신용정보를 처리하는 것
  - 신용정보법 제2조 제17호. 가명처리는 제15호, 가명정보는 제16호.
- Q: 신용정보법이 가명정보 제공 목적으로 개인정보 보호법보다 넓게 인정하는 부분 — 통계작성에 상업적 목적의 시장조사를, 연구에 산업적 연구를 포함한다
  - 신용정보법 제32조 제6항 제9호의2.
- Q: 신용정보법에서 신용정보회사등이 가명처리나 익명처리를 한 경우 조치 기록을 보존하는 기간 — 3년
  - 처리한 날짜, 항목, 사유와 근거를 남긴다(제40조의2 제8항).
- Q: 신용정보법에서 정보집합물 결합과 익명처리 적정성 평가를 맡도록 금융위원회가 지정하는 기관 — 데이터전문기관
  - 신용정보법 제26조의4.

## 개인정보 활용과 비식별 조치

- Q: 개인정보 비식별 조치 가이드라인(2016, 관계부처 합동)의 4단계 — 사전검토 → 비식별 조치 → 적정성 평가 → 사후관리
- **총계처리 (Aggregation)** — 개별 값 대신 합계나 평균 같은 집계값만 남겨 개인 단위가 드러나지 않게 하는 비식별 기법
- **데이터 삭제 (Data Reduction)** — 식별자나 식별에 쓰일 수 있는 속성을 아예 지우는 비식별 기법. 예: 주민등록번호 열 제거
- **데이터 범주화 (Data Suppression)** — 정확한 값을 구간이나 상위 범주로 바꿔 표시하는 비식별 기법. 예: 37세 → 30대
- **데이터 마스킹 (Data Masking)** — 식별에 쓰이는 값의 일부를 별표 같은 문자로 가리는 비식별 기법. 예: 홍*동
- Q: 이름을 무작위 코드로 바꾸는 휴리스틱 가명화, 암호화, 교환 방법이 속하는 비식별 기법 — 가명처리
- **k-익명성 (k-Anonymity)** — 준식별자가 같은 레코드가 적어도 k개씩 있도록 만들어 특정인을 k명 중 하나 이상으로 좁히지 못하게 하는 프라이버시 모델
  - 같은 그룹의 민감정보가 모두 같으면 동질성 공격에 뚫린다.
- **l-다양성 (l-Diversity)** — 준식별자가 같은 각 그룹 안에 민감정보 값이 적어도 l가지 이상 섞이도록 해 동질성 공격과 배경지식 공격을 막는 프라이버시 모델
- **t-근접성 (t-Closeness)** — 각 그룹 안 민감정보의 분포가 전체 분포와 t 이하로만 차이 나게 해 쏠림 공격과 유사성 공격을 막는 프라이버시 모델
- Q: k-익명성, l-다양성, t-근접성 중 동질성 공격을 막지 못하는 것 — k-익명성
- **재식별 (Re-identification)** — 비식별 조치된 데이터를 다른 정보와 결합하거나 추론해 다시 특정 개인을 알아내는 것
