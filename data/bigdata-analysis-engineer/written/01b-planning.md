# 빅데이터 분석 기획 (데이터분석 계획, 데이터 수집 및 저장 계획)

> 필기 1과목 뒷부분. 출제기준(2024.1.1~2026.12.31)의 주요항목 데이터분석 계획과 데이터 수집 및 저장 계획을 다룬다.

## 분석 로드맵 설정

- **최적화 (Optimization)** — 분석 대상도 알고 분석 방법도 아는 상태에서 개선을 노리는 분석 주제 유형
- **솔루션 (Solution)** — 분석 대상은 알지만 분석 방법을 몰라 해법을 찾아야 하는 분석 주제 유형
- **통찰 (Insight)** — 분석 방법은 알지만 분석 대상이 정해지지 않아, 기존 방법으로 새로운 시사점을 끌어내는 분석 주제 유형
- **발견 (Discovery)** — 분석 대상도 방법도 모르는 상태에서 새로운 주제를 찾아내는 분석 주제 유형
- Q: 분석 과제 우선순위를 평가하는 두 축 — 시급성(전략적 중요도)과 난이도(실행 용이성)
- Q: 시급성과 난이도로 과제를 배치할 때 가장 먼저 추진하는 과제 — 시급성이 현재이고 난이도가 쉬운 과제
  - 가장 나중은 시급성이 미래이고 난이도가 어려운 과제다.
- Q: 분석 마스터플랜 로드맵의 단계 순서 — 분석 체계 도입 → 분석 유효성 검증 → 분석 확산 및 고도화
- Q: 분석 거버넌스 체계의 구성 요소 다섯 가지 — 조직(Organization), 프로세스(Process), 시스템(System), 데이터(Data), 분석 인력(Human Resource)
- Q: 데이터 거버넌스의 3요소 — 원칙(Principle), 조직(Organization), 프로세스(Process)
- Q: 분석 성숙도 모델의 단계 순서 — 도입 → 활용 → 확산 → 최적화
- **도입 단계 (Introduction)** — 분석을 막 시작해 환경과 시스템을 구축하는 성숙도 단계. 실적 분석과 통계 수준에 머문다
- **활용 단계 (Utilization)** — 분석 결과를 실제 업무에 적용하기 시작한 성숙도 단계. 미래 예측과 운영 데이터 기반 분석이 나타난다
- **확산 단계 (Diffusion)** — 전사 차원에서 분석을 관리하고 공유하는 성숙도 단계. 분석 전문 조직과 전사 성과 실시간 분석이 갖춰진다
- **최적화 단계 (Optimization Stage)** — 분석을 진화시켜 혁신과 성과 향상에 기여하는 성숙도 단계. 외부 환경 분석과 최적화 업무가 자리 잡는다
- Q: 분석 준비도 진단의 여섯 영역 — 분석 업무 파악, 인력 및 조직, 분석 기법, 분석 데이터, 분석 문화, IT 인프라
- **준비형 (Preparing Type)** — 분석 준비도와 성숙도가 모두 낮아 사전 준비가 필요한 기업 유형
- **정착형 (Establishing Type)** — 준비도는 낮지만 일부 부서에서 분석을 이미 하고 있어, 그 수준을 안정시켜야 하는 기업 유형
- **도입형 (Introducing Type)** — 성숙도는 낮지만 조직, 인력, 인프라 같은 준비도가 높아 바로 분석을 도입할 수 있는 기업 유형
- **확산형 (Diffusing Type)** — 준비도와 성숙도가 모두 높아 지속적으로 분석을 확산해야 하는 기업 유형

## 분석 문제 정의

- **하향식 접근법 (Top-down Approach)** — 해결할 문제가 주어진 상태에서 해법을 체계적으로 찾아가는 분석 과제 발굴 방식
  - 절차: 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토
- **상향식 접근법 (Bottom-up Approach)** — 문제를 먼저 정하지 않고 데이터를 살펴 패턴과 통찰에서 문제를 끌어내는 분석 과제 발굴 방식. 비지도학습을 많이 쓴다
- Q: 문제의 구조가 분명하고 해법을 체계적으로 찾을 때와, 문제 자체가 불분명해 데이터에서 시작할 때 각각 맞는 접근법 — 앞은 하향식, 뒤는 상향식
- Q: 디자인 사고에서 상향식과 하향식의 역할 — 상향식으로 가능한 옵션을 넓히는 발산(Diverge), 하향식으로 좁히는 수렴(Converge)을 반복한다
- Q: 비즈니스 모델 캔버스로 문제를 탐색할 때 쓰는 다섯 영역 — 업무, 제품, 고객, 규제와 감사, 지원 인프라
- **STEEP** — 사회(Social), 기술(Technological), 경제(Economic), 환경(Environmental), 정치(Political) 영역으로 나눠 거시 환경의 분석 기회를 찾는 틀
- Q: 하향식 접근법의 타당성 검토에서 따지는 두 측면 — 경제적 타당성, 데이터 및 기술적 타당성
- Q: 문제 정의 단계에서 비즈니스 문제를 바꿔 놓는 대상 — 데이터 분석 문제
  - 예: 고객 이탈 증가 → 이탈 가능성이 높은 고객을 예측하는 분류 문제
- **프로토타이핑 접근법 (Prototyping Approach)** — 일단 분석을 시도해 결과를 보고 반복 개선하며 문제를 구체화하는 상향식 방식. 문제나 데이터가 불명확할 때 쓴다
- Q: 분석 과제 관리에서 고려하는 다섯 영역 — 데이터 크기(Data Size), 데이터 복잡성(Data Complexity), 속도(Speed), 분석 복잡성(Analytic Complexity), 정확도와 정밀도(Accuracy & Precision)
- Q: 분석 과제 관리에서 정확도(Accuracy)와 정밀도(Precision)의 차이 — 정확도는 실제값과의 차이가 작은 정도, 정밀도는 반복해서 측정했을 때 결과가 흩어지지 않는 정도
  - 둘은 트레이드오프 관계인 경우가 많다.

## 데이터 분석 방안과 방법론

- Q: 분석 방법론의 구성 요소 — 절차, 방법, 도구와 기법, 템플릿과 산출물
- **폭포수 모델 (Waterfall Model)** — 단계를 순차적으로 진행하고 이전 단계가 끝나야 다음 단계로 넘어가는 개발 모델
- **나선형 모델 (Spiral Model)** — 계획, 위험 분석, 개발, 평가를 반복하며 점진적으로 완성하는 모델. 위험 관리에 강하다
- **KDD (Knowledge Discovery in Databases)** — 데이터에서 유용한 지식을 찾는 과정을 정리한 방법론
  - 절차: 데이터셋 선택 → 전처리 → 변환 → 데이터 마이닝 → 해석과 평가
- **CRISP-DM (Cross Industry Standard Process for Data Mining)** — 업계 공통의 데이터 마이닝 표준 절차로, 단계 사이를 오가는 반복을 허용하는 방법론
  - 절차: 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개
- Q: CRISP-DM의 4레벨 구조 — 단계(Phase) → 일반화 태스크 → 세분화 태스크 → 프로세스 실행
- Q: CRISP-DM에는 있고 KDD에는 없는 단계 두 가지 — 업무 이해, 전개
- Q: CRISP-DM에서 모델링 결과를 보고 되돌아가는 일이 잦은 단계 — 데이터 준비
  - 업무 이해와 데이터 이해 사이도 양방향으로 오간다.
- **SEMMA** — SAS가 제안한 분석 절차로 샘플링(Sample), 탐색(Explore), 수정(Modify), 모델링(Model), 평가(Assess) 다섯 단계를 거친다
- Q: 빅데이터 분석 방법론의 다섯 단계 — 분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개
- Q: 빅데이터 분석 방법론의 3계층 구조 — 단계(Phase) → 태스크(Task) → 스텝(Step)
- Q: 빅데이터 분석 방법론의 분석 기획 단계 태스크 세 가지 — 비즈니스 이해 및 범위 설정, 프로젝트 정의 및 계획 수립, 프로젝트 위험 계획 수립
- Q: 프로젝트 위험에 대응하는 네 가지 방식 — 회피(Avoid), 전이(Transfer), 완화(Mitigate), 수용(Accept)
- Q: 빅데이터 분석 방법론에서 텍스트 분석, 탐색적 분석, 모델링, 모델 평가 및 검증이 속하는 단계 — 데이터 분석
- **WBS (Work Breakdown Structure)** — 프로젝트 산출물을 기준으로 해야 할 작업을 계층적으로 잘게 나눈 구조도
- **SOW (Statement of Work)** — 프로젝트의 범위, 산출물, 일정 같은 수행 내용을 정리한 작업 명세서

## 분석 작업 계획

- Q: 데이터 확보 계획 수립 절차 — 목표 정의 → 요구사항 도출 → 예산안 수립 → 계획 수립
- Q: 내부 데이터와 외부 데이터를 확보할 때의 차이 — 내부는 부서 간 협의와 관리 권한 확인이 중심, 외부는 구매나 수집 비용, 저작권과 개인정보 같은 법적 문제 검토가 중심
- Q: 데이터 분석 과제의 위험을 줄이기 위해 계획 단계에서 먼저 확인할 것 — 필요한 데이터의 확보 가능성과 품질
- Q: 분석 작업 일정 계획에서 데이터 분석 단계의 반복 범위를 미리 정해 두는 이유 — 모델링과 평가가 반복되며 일정이 늘어지는 것을 막기 위해

## 데이터 수집

- **크롤링 (Crawling)** — 웹 페이지의 링크를 따라다니며 문서를 자동으로 내려받아 모으는 수집 기법
- **스크래핑 (Scraping)** — 웹 페이지에서 필요한 부분의 값을 골라 추출하는 수집 기법
- **Open API** — 기관이나 서비스가 공개한 인터페이스로 정해진 형식의 데이터를 요청해 받아오는 수집 방식
- **RSS (Really Simple Syndication)** — 사이트가 갱신 내용을 XML 형식으로 배포하면 구독해 새 글을 받아오는 방식
- **ETL (Extract, Transform, Load)** — 원천 시스템에서 데이터를 추출해 정제, 변환한 뒤 목적 저장소에 적재하는 일괄 처리 과정
  - 데이터 레이크 환경에서는 적재를 먼저 하고 변환을 나중에 하는 ELT를 쓰기도 한다.
- **CDC (Change Data Capture)** — 원천 데이터베이스에서 바뀐 부분만 감지해 대상 시스템에 실시간으로 반영하는 수집 기법
- **EAI (Enterprise Application Integration)** — 기업 내 여러 애플리케이션을 허브로 연결해 데이터와 프로세스를 실시간 연동하는 통합 방식
- **카프카 (Apache Kafka)** — 대량의 이벤트 스트림을 발행-구독 방식으로 주고받는 분산 메시징 플랫폼
- Q: 원천 데이터 성격에 따른 수집 기술 짝 — 정형은 ETL, DB 연동, Sqoop / 반정형은 Open API, 크롤링, 로그 수집기 / 비정형은 크롤링, 스크래핑, 파일 수집

## 데이터 유형 및 속성 파악

- **명목척도 (Nominal Scale)** — 대상을 구분하려고 이름이나 번호만 붙인 측정 수준. 순서와 크기 비교가 의미 없다. 예: 성별, 혈액형
- **서열척도 (Ordinal Scale)** — 순서는 의미 있지만 간격은 같다고 볼 수 없는 측정 수준. 예: 학점 등급, 만족도 5단계
- **등간척도 (Interval Scale)** — 간격이 같아 더하고 빼는 것은 의미 있지만 절대 0점이 없어 비율 비교는 못 하는 측정 수준. 예: 섭씨 온도, IQ
- **비율척도 (Ratio Scale)** — 절대 0점이 있어 사칙연산과 비율 비교가 모두 가능한 측정 수준. 예: 무게, 매출액, 나이
- Q: "30도는 15도보다 두 배 덥다"가 틀린 말인 이유 — 섭씨는 등간척도라 절대 0점이 없어 비율 비교가 성립하지 않는다
- Q: 이산형 변수와 연속형 변수의 차이 — 이산형은 셀 수 있는 값만 가진다(예: 방문 횟수), 연속형은 구간 안의 모든 실수 값을 가질 수 있다(예: 키)

## 데이터 변환

- **평활화 (Smoothing)** — 구간화나 군집화로 데이터의 잡음을 줄여 추세를 매끄럽게 만드는 변환
- **집계 (Aggregation)** — 여러 레코드를 합계나 평균으로 묶어 요약된 단위로 바꾸는 변환. 예: 일별 매출 → 월별 매출
- **일반화 (Generalization)** — 세부 값을 더 상위 개념으로 바꿔 범용적으로 만드는 변환. 예: 동 단위 주소 → 시 단위
- **속성 생성 (Attribute Construction)** — 기존 속성을 조합해 분석에 도움이 되는 새 속성을 만드는 변환
- Q: 서로 다른 시스템에서 모은 데이터의 날짜 형식과 단위를 하나로 맞추는 작업 — 데이터 표준화(형식 통일)

## 데이터 품질 검증

- Q: 정형 데이터 품질 기준 다섯 가지 — 완전성, 유일성, 유효성, 일관성, 정확성
- **완전성 (Completeness)** — 필수 항목에 빠진 값 없이 데이터가 다 채워져 있는 정도
- **유일성 (Uniqueness)** — 하나만 있어야 할 값이 중복되지 않는 정도. 예: 같은 고객번호가 두 번 등록되지 않음
- **유효성 (Validity)** — 값이 정해진 형식, 범위, 업무 규칙을 지키는 정도. 예: 월 값이 1~12 사이
- **일관성 (Consistency)** — 같은 대상의 값이 여러 테이블과 시스템에서 서로 모순 없이 맞는 정도
- Q: 비정형 데이터(소프트웨어 산출물 관점) 품질 기준 다섯 가지 — 기능성, 신뢰성, 사용성, 효율성, 이식성
- **데이터 프로파일링 (Data Profiling)** — 데이터의 분포, 결측 비율, 값의 패턴과 범위를 통계적으로 훑어 품질 문제를 찾아내는 진단 기법
- Q: 품질 진단에서 전화번호 열의 자릿수와 하이픈 위치가 규칙에 맞는지 보는 분석 — 문자열 패턴 분석
- **메타데이터 (Metadata)** — 데이터의 구조, 형식, 의미, 출처처럼 데이터 자체를 설명하는 데이터. 품질 진단의 출발점이 된다

## 데이터 적재 및 저장

- Q: 수집한 로그를 실시간으로 적재하는 데 쓰는 오픈소스 수집, 적재 도구의 예 — Fluentd, Flume, Logstash, Scribe
- Q: 대용량 비정형 데이터와 정형 데이터의 저장소로 흔히 고르는 짝 — 비정형은 분산 파일 시스템(HDFS)이나 NoSQL, 정형은 RDBMS나 데이터 웨어하우스
- **DAS (Direct Attached Storage)** — 서버에 저장 장치를 직접 연결해 쓰는 방식. 다른 서버와 공유하기 어렵다
- **NAS (Network Attached Storage)** — 네트워크(LAN)를 통해 파일 단위로 여러 서버가 공유하는 저장 장치
- **SAN (Storage Area Network)** — 서버와 저장 장치를 전용 고속 네트워크로 묶어 블록 단위로 접근하게 하는 저장 구조
- **객체 스토리지 (Object Storage)** — 파일을 메타데이터와 고유 ID를 가진 객체로 평면 공간에 저장하는 클라우드형 저장 방식. 예: Amazon S3
- Q: 데이터 적재 방식 중 일정 주기마다 모아 한꺼번에 넣는 것과 발생 즉시 넣는 것 — 배치(일괄) 적재와 실시간(스트리밍) 적재
- Q: 분산 저장 시스템이 같은 블록을 여러 노드에 복제해 두는 이유 — 일부 노드가 고장 나도 데이터를 잃지 않고 계속 서비스하기 위해(내결함성)
