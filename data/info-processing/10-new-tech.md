# 응용 SW 기초 기술 · 신기술

## 클라우드 서비스

- **IaaS (Infrastructure as a Service)** — 서버·스토리지·네트워크 같은 컴퓨팅 기반 자원을 가상화해 필요한 만큼 빌려 쓰게 하는 서비스
  - 예: AWS EC2
- **PaaS (Platform as a Service)** — 운영체제·미들웨어·개발 도구 등 애플리케이션을 개발하고 실행할 환경을 제공해, 사용자는 코드에만 집중하게 하는 서비스
  - 예: Google App Engine, Heroku
- **SaaS (Software as a Service)** — 완성된 응용 프로그램을 설치 없이 웹 브라우저로 바로 이용하게 하는 서비스
  - 예: Gmail, Microsoft 365

## 가상화

- **가상화 (Virtualization)** — 하나의 물리 자원을 여러 개의 논리 자원처럼 나눠 쓰거나, 여러 물리 자원을 하나처럼 묶어 쓰게 하는 기술
- **하이퍼바이저 (Hypervisor)** — 물리 하드웨어 위에서 여러 게스트 운영체제(가상 머신)를 동시에 실행하고 관리하는 소프트웨어 계층
  - Type 1(베어메탈형), Type 2(호스트형)
- **컨테이너 (Container)** — 게스트 운영체제 없이 호스트 OS 커널을 공유하면서 애플리케이션을 프로세스 단위로 격리해, 가상 머신보다 가볍고 빠르게 실행하는 방식
- **도커 (Docker)** — 애플리케이션과 실행에 필요한 라이브러리·설정을 이미지로 묶어 어느 환경에서든 똑같이 띄울 수 있게 하는 대표적 오픈소스 컨테이너 엔진

## 소프트웨어 정의 기술

- **SDN (Software Defined Networking)** — 네트워크 장비의 제어 기능과 패킷 전달 기능을 분리해, 중앙 컨트롤러 프로그램으로 네트워크 전체를 관리하는 기술
  - 대표 프로토콜: OpenFlow
- **SDS (Software Defined Storage)** — 서로 다른 물리 저장 장치를 가상화해 하나의 자원 풀로 묶고, 용량 할당과 정책을 프로그램으로 관리하는 기술
- **SDC (Software Defined Computing)** — 서버의 CPU·메모리 같은 연산 자원을 가상화해 필요에 따라 프로그램으로 할당하고 관리하는 기술
- **SDDC (Software Defined Data Center)** — 서버·네트워크·스토리지 등 전산 시설 전체의 자원을 가상화해 사람의 개입 없이 프로그램으로 통합 운영하는 기술

## 스토리지

- **스토리지 (Storage)** — 대용량 데이터를 담기 위해 서버와 별도로 구성하는 저장 장치나 저장 시스템
  - 연결 방식: DAS, NAS, SAN
- **DAS (Direct Attached Storage)** — 서버에 저장 장치를 케이블로 직접 붙이는 방식으로, 구성이 간단하지만 다른 서버와의 공유와 확장이 어렵다
- **NAS (Network Attached Storage)** — 저장 장치를 LAN에 연결해 여러 서버·클라이언트가 파일 단위로 공유하는 방식
  - 프로토콜: NFS, SMB/CIFS
- **SAN (Storage Area Network)** — 서버와 저장 장치를 광 채널(Fibre Channel) 같은 전용 고속망으로 연결해 블록 단위로 접근하게 하는 방식
- **RAID (Redundant Array of Independent Disks)** — 여러 개의 디스크를 하나처럼 묶어 성능을 높이거나, 장애에 대비해 데이터를 중복 저장하는 기술
  - 0: 스트라이핑, 1: 미러링, 5: 분산 패리티, 6: 이중 패리티

## 재해 복구 사이트 유형 (미핫웜콜)

- **미러 사이트 (Mirror Site)** — 주 센터와 같은 수준의 시스템을 원격지에 두고 둘 다 동시에 가동(Active-Active)하는 방식으로, 복구 시간이 사실상 0에 가깝다
- **핫 사이트 (Hot Site)** — 주 센터와 같은 장비를 대기 상태(Active-Standby)로 두고 데이터를 실시간 동기화해, 보통 4시간 이내에 업무를 되살리는 방식
- **웜 사이트 (Warm Site)** — 중요도가 높은 업무 위주로 일부 장비만 갖추고 데이터는 주기적으로 백업해 두어, 수일~수주 안에 되살리는 방식
- **콜드 사이트 (Cold Site)** — 전원·공간 같은 최소 시설만 확보해 두고 재해가 난 뒤에 장비를 들여와 구축하므로, 수주~수개월이 걸리는 방식

## 재해 복구 지표

- **재해 복구 시스템 (DRS, Disaster Recovery System)** — 재난으로 주 전산 센터가 멈출 경우에 대비해 원격지에 데이터와 시스템을 복제해 두고 업무를 이어 가도록 갖춘 체계
  - 유형: 미러·핫·웜·콜드 사이트
- **RTO (Recovery Time Objective)** — 재해로 업무가 멈춘 뒤 서비스를 다시 가동하기까지 조직이 허용할 수 있는 최대 중단 시간 목표
- **RPO (Recovery Point Objective)** — 재해 시 데이터를 어느 시점까지 되살려야 하는지, 즉 감수할 수 있는 최대 데이터 손실 구간을 정한 목표
- **BIA (Business Impact Analysis)** — 업무가 중단될 때 생기는 재무·운영상 손실 규모를 평가해 업무별 복구 우선순위와 목표 시간을 정하는 과정

## 빅데이터 처리

- **빅데이터 (Big Data)** — 기존 도구로는 수집·저장·분석이 어려울 만큼 방대하고 빠르게, 다양한 형태로 쏟아지는 데이터
  - 3V: Volume, Velocity, Variety (+Value, Veracity)
- **하둡 (Hadoop)** — 값싼 범용 서버 여러 대를 묶어 대용량 데이터를 분산 저장하고 분산 처리하는 아파치 재단의 오픈소스 프레임워크
- **맵리듀스 (MapReduce)** — 데이터를 키-값 쌍으로 변환·분류하는 단계와 같은 키끼리 모아 집계하는 단계로 나눠 여러 노드에서 병렬 처리하는 프로그래밍 모델
- **스쿱 (Sqoop)** — 하둡과 관계형 데이터베이스 사이에서 대량의 데이터를 가져오고 내보내는 전송 도구
- **NoSQL (Not Only SQL)** — 고정 스키마 없이 키-값·문서·컬럼·그래프 형태로 데이터를 저장해, 비정형·반정형 데이터와 수평 확장에 강한 비관계형 데이터베이스
  - 예: MongoDB, Cassandra, Redis
- **스크래피 (Scrapy)** — 웹 페이지를 자동으로 돌아다니며 원하는 데이터를 추출(크롤링)하는 파이썬 기반 오픈소스 프레임워크

## 데이터 분석·저장

- **OLAP (Online Analytical Processing)** — 다차원으로 구성한 데이터를 사용자가 여러 관점에서 대화식으로 집계·조회하며 의사결정에 활용하는 처리 기술
  - 연산: 롤업, 드릴다운, 슬라이싱, 다이싱, 피보팅
- **데이터 웨어하우스 (Data Warehouse)** — 여러 운영 시스템의 데이터를 추출·변환해 주제별로 통합하고 시간 흐름에 따라 쌓아 두는 의사결정 지원용 대규모 저장소
  - 특징: 주제 지향, 통합, 시계열, 비휘발
- **데이터 마트 (Data Mart)** — 전사 통합 저장소 가운데 특정 부서나 업무 분야에 필요한 데이터만 따로 떼어 구성한 소규모 분석용 저장소
- **데이터 마이닝 (Data Mining)** — 대량의 데이터에서 통계·기계학습 기법으로 숨어 있는 패턴·규칙·상관관계를 찾아내는 기법
  - 기법: 분류, 연관 규칙, 군집, 연속 규칙
- **텍스트 마이닝 (Text Mining)** — 뉴스·리뷰 같은 비정형 문서에서 자연어 처리로 의미 있는 키워드·주제·감성 같은 정보를 뽑아내는 기법
- **웹 마이닝 (Web Mining)** — 인터넷 페이지의 내용, 페이지 사이의 링크 구조, 사용자 접속 기록을 분석해 유용한 정보를 찾아내는 기법
- **다크 데이터 (Dark Data)** — 수집·저장만 해 두고 분석이나 의사결정에는 한 번도 쓰이지 않은 채 쌓여 있는 데이터. 저장 비용과 보안 위험만 키우는 경우가 많다

## 분산 시스템 이론

- **CAP 이론 (CAP Theorem)** — 분산 시스템은 일관성·가용성·분할 내성 세 가지를 동시에 모두 만족할 수 없고 최대 둘만 보장할 수 있다는 이론
  - 네트워크 분할이 생기면 일관성과 가용성 중 하나를 포기해야 함

## 웹·시맨틱

- **시맨틱 웹 (Semantic Web)** — 인터넷 문서에 컴퓨터가 이해할 수 있는 의미 정보를 붙여, 사람 대신 기계가 정보를 해석·추론·처리하게 하는 차세대 인터넷 구상
  - 팀 버너스리 제안, 기반 기술: RDF, OWL
- **온톨로지 (Ontology)** — 특정 분야의 개념과 개념 사이의 관계를 컴퓨터가 처리할 수 있도록 형식적으로 정의해 둔 지식 체계
- **매시업 (Mashup)** — 여러 서비스가 공개한 API나 데이터를 섞어 조합해 새로운 웹 서비스를 만들어 내는 기법
  - 예: 지도 API + 부동산 매물 정보
- **CSS (Cascading Style Sheets)** — HTML 문서의 글꼴·색상·배치 같은 표현 방식을 내용과 분리해 정의하는 언어
- **하이퍼텍스트 (Hypertext)** — 문서 안의 단어나 그림을 누르면 다른 문서·위치로 바로 이동하도록 링크로 엮은 텍스트. 웹 문서 언어와 웹 전송 규약 이름의 앞부분이 여기서 왔다
- **HTTP (HyperText Transfer Protocol)** — 웹 브라우저와 웹 서버가 HTML 문서 등 웹 자원을 요청과 응답으로 주고받는 응용 계층 통신 규약. 기본 포트는 80이고 이전 요청 상태를 기억하지 않는다
- **LOD (Linked Open Data)** — 누구나 쓸 수 있게 공개한 데이터를 URI로 식별하고 서로 링크로 이어, 웹 전체를 하나의 거대한 데이터베이스처럼 활용하게 하는 방식

## 블록체인·가상 세계

- **블록체인 (Blockchain)** — 거래 내역 묶음마다 직전 묶음의 해시값을 넣어 차례로 이어 붙이고, P2P 참여자 모두가 사본을 나눠 보관해 위·변조를 어렵게 한 분산 원장 기술
- **NFT (Non-Fungible Token)** — 분산 원장에 기록되어 하나하나가 고유한 식별값을 가지므로 서로 맞바꿀 수 없는 디지털 자산 증명으로, 그림·게임 아이템 등의 소유권 증명에 쓴다
- **메타버스 (Metaverse)** — 현실처럼 사회·경제·문화 활동이 이루어지는 3차원 가상 세계로, 사람들이 아바타를 통해 교류하는 공간

## AI 라이브러리

- **딥러닝 (Deep Learning)** — 은닉층을 여러 겹 쌓은 인공 신경망으로 데이터의 특징을 사람이 지정하지 않아도 스스로 추출하게 하는 기계학습의 한 분야
- **사이킷런 (scikit-learn)** — 분류·회귀·군집·차원 축소 같은 전통적 기계학습 알고리즘을 일관된 API로 제공하는 파이썬 오픈소스 라이브러리
- **텐서플로 (TensorFlow)** — 구글 브레인 팀이 개발한 오픈소스 딥러닝 프레임워크로, 다차원 배열이 흐르는 연산 그래프로 모델을 구성하며 Keras를 고수준 API로 포함한다
- **파이토치 (PyTorch)** — 메타(페이스북)가 주도해 개발한 오픈소스 딥러닝 프레임워크로, 실행하면서 계산 그래프를 만드는 동적 방식(Define-by-Run)이라 디버깅이 쉽다

## 운영 관리

- **APM (Application Performance Management)** — 애플리케이션의 응답 시간·트랜잭션 처리량·자원 사용률·오류를 실시간으로 추적해 병목과 장애 지점을 찾아 주는 도구
- **레거시 시스템 (Legacy System)** — 오래전에 구축되어 기술은 낡았지만 핵심 업무를 계속 처리하고 있어 쉽게 교체하기 어려운 기존 시스템
- **GIS (Geographic Information System)** — 위치·지형 같은 공간 정보를 속성 데이터와 함께 수집·저장·분석해 지도 형태로 보여 주는 시스템
