# 소프트웨어 개발 보안 · 정보 보안

## 정보 보안 3요소 (기무가)

- **기밀성 (Confidentiality)** — 허가받은 사용자만 정보를 열람할 수 있게 하여 권한 없는 노출과 유출을 막는 성질
- **무결성 (Integrity)** — 정보가 권한 없이 생성·변경·삭제되지 않고 정확하고 완전한 상태로 유지되는 성질
- **가용성 (Availability)** — 권한을 가진 사용자가 필요한 순간에 지체 없이 정보와 시스템을 쓸 수 있는 성질

## 정보 보안 추가 요소

- **인증성 (Authenticity)** — 정보를 주고받는 상대나 정보의 출처가 주장하는 그 대상이 맞는지 확인할 수 있는 성질
- **부인 방지 (Non-repudiation)** — 송신·수신 증거를 남겨 두어 나중에 보낸 사실이나 받은 사실을 부정하지 못하게 하는 성질

## 접근 통제 절차

- **식별 (Identification)** — 사용자가 ID나 계정명을 제시해 자신이 누구인지 시스템에 밝히는, 접근 통제의 첫 단계
- **인증 (Authentication)** — 앞 단계에서 밝힌 신원이 진짜 본인인지 비밀번호·OTP·지문 같은 생체 정보 등으로 검증하는 단계
- **인가 (Authorization)** — 검증을 통과한 사용자에게 어떤 자원에 어떤 작업까지 허용할지 권한을 부여하는 단계
- **책임 추적성 (Accountability)** — 사용자의 행위를 기록해 두어 누가 언제 무엇을 했는지 나중에 추적·감사할 수 있게 하는 단계
- Q: 접근 통제 절차를 순서대로 쓰면? — 식별 → 인증 → 인가 → 책임 추적성

## 접근 통제 정책

- **강제적 접근 통제 (MAC, Mandatory Access Control)** — 주체의 비밀 취급 인가 등급과 객체의 보안 등급(레이블)을 비교해 시스템이 정한 규칙대로만 접근을 허용하는 정책
- **임의적 접근 통제 (DAC, Discretionary Access Control)** — 데이터 소유자가 사용자 신원(ID)을 근거로 다른 사용자에게 접근 권한을 재량껏 주고 회수하는 정책
  - 구현 예: 접근 제어 목록(ACL)
- **역할 기반 접근 통제 (RBAC, Role Based Access Control)** — 권한을 개인이 아닌 조직 내 직무·직책에 묶어 두고, 사용자를 그 직무에 배정해 간접적으로 권한을 갖게 하는 정책

## 접근 통제 보안 모델

- **벨-라파둘라 모델 (Bell-LaPadula Model)** — 기밀성 유지를 목적으로 한 군사용 모델로, 자기보다 높은 등급은 읽지 못하고 낮은 등급에는 쓰지 못하게 하는 모델
  - No Read Up, No Write Down
- **비바 모델 (Biba Model)** — 무결성 유지를 목적으로 한 모델로, 자기보다 낮은 등급은 읽지 못하고 높은 등급에는 쓰지 못하게 하는 모델
  - No Read Down, No Write Up
- **클락-윌슨 모델 (Clark-Wilson Model)** — 상업 환경의 무결성을 위해 사용자가 데이터를 직접 고치지 못하고 검증된 프로그램(정형 트랜잭션)을 거쳐서만 변경하게 하는 모델
  - 핵심: 직무 분리
- **만리장성 모델 (Chinese Wall Model, Brewer-Nash)** — 이해가 충돌하는 경쟁사들의 정보에 한 사람이 동시에 접근하지 못하도록, 이미 접근한 정보에 따라 이후 권한이 달라지는 모델

## 대칭 키 암호

- **대칭 키 암호 (Symmetric Key Cryptography)** — 암호화와 복호화에 같은 비밀 키를 쓰는 방식으로, 속도는 빠르지만 키 분배가 어렵고 사용자가 늘면 키 개수가 급증한다
  - n명이 통신할 때 필요한 키 수 n(n-1)/2
- **DES (Data Encryption Standard)** — 1970년대 미국 연방 표준으로 채택된 블록 암호로, 64비트 블록을 56비트 키로 16라운드 처리하는 Feistel 구조 방식
- **AES (Advanced Encryption Standard)** — 앞선 56비트 키 표준을 대체하려고 공모로 선정된 미국 표준 블록 암호로, 128비트 블록에 128·192·256비트 키를 쓰는 SPN 구조 방식
- **SEED** — 1999년 한국인터넷진흥원(KISA)이 개발한 국내 표준 블록 암호로, 128비트 블록을 Feistel 구조로 처리하는 방식
- **ARIA (Academy, Research Institute, Agency)** — 2004년 국가정보원과 학계·연구소가 함께 개발한 국내 표준 블록 암호로, 128비트 블록에 128·192·256비트 키를 쓰는 SPN 구조 방식
- **IDEA (International Data Encryption Algorithm)** — 스위스에서 개발된 블록 암호로, 64비트 블록을 128비트 키로 처리하며 성질이 다른 세 가지 대수 연산을 섞어 쓰는 방식
  - PGP 전자우편 보안에 사용
- **RC4 (Rivest Cipher 4)** — 키로 만든 의사 난수 키 스트림을 평문과 바이트 단위로 XOR하는 스트림 암호로, 과거 SSL·WEP에 쓰였으나 취약점이 밝혀진 방식
- **LFSR (Linear Feedback Shift Register)** — 일부 비트를 XOR한 결과를 다시 입력으로 넣으며 비트를 한 칸씩 밀어내는 레지스터로, 스트림 암호의 키 스트림 생성에 쓰이는 회로
- **Skipjack** — 미국 국가안보국(NSA)이 개발한 블록 암호로, 64비트 블록을 80비트 키로 처리한다. 음성 통신 암호화용 클리퍼 칩에 탑재되었다

## 비대칭 키 암호

- **비대칭 키 암호 (Asymmetric Key Cryptography)** — 누구에게나 알리는 키와 본인만 가진 키 한 쌍을 써서, 한쪽으로 암호화하면 다른 쪽으로만 풀리게 하는 방식
  - 키 분배는 쉽지만 연산이 느림, 필요한 키 수 2n
- **RSA (Rivest-Shamir-Adleman)** — 1977년 MIT의 세 연구자가 고안한 공개 키 방식으로, 큰 수를 소인수분해하기 어렵다는 점에 안전성을 둔 방식
- **DSA (Digital Signature Algorithm)** — 미국 NIST 표준(DSS)으로 채택된, 메시지 서명의 생성과 검증에만 쓰는 알고리즘으로 이산 대수 문제의 어려움에 기반한다
- **ECC (Elliptic Curve Cryptography)** — y² = x³ + ax + b 형태 곡선 위의 점 연산에 기반한 공개 키 방식으로, 소인수분해 기반 방식보다 훨씬 짧은 키로 같은 강도를 내는 방식
- **디피-헬먼 키 교환 (Diffie-Hellman Key Exchange)** — 비밀 값을 직접 보내지 않고 공개된 값만 주고받아 양측이 같은 대칭 키를 만들어 내는 방식으로, 이산 대수 문제에 기반한다
  - 1976년 최초로 공개 키 개념 제시
- **엘가말 (ElGamal)** — 이산 대수 문제에 기반한 공개 키 방식으로, 같은 평문도 매번 다른 암호문이 나오며 암호문 길이가 평문의 약 두 배가 되는 방식

## 해시

- **SHA (Secure Hash Algorithm)** — NIST가 표준으로 정한 해시 함수 계열로, 160비트를 출력하는 1세대 이후 224~512비트 출력의 2세대와 Keccak 기반 3세대가 나왔다
- **MD5 (Message-Digest Algorithm 5)** — 로널드 리베스트가 만든 128비트 출력 해시 함수로, 충돌을 만드는 공격이 실증되어 보안 용도로는 더 이상 권장되지 않는 방식

## 해시 함수의 특성 (역제충)

- **역상 저항성 (Preimage Resistance)** — 해시값만 주어졌을 때 그 값을 만들어 내는 입력을 찾아내는 것이 계산상 불가능한 성질
  - 일방향성이라고도 함
- **제2 역상 저항성 (Second Preimage Resistance)** — 입력 하나가 주어졌을 때 그것과 해시값이 같은 다른 입력을 찾아내는 것이 계산상 불가능한 성질
- **충돌 저항성 (Collision Resistance)** — 해시값이 같은 서로 다른 두 입력을 아무 쌍이나 골라 찾아내는 것조차 계산상 불가능한 성질

## 암호 응용

- **비트로커 (BitLocker)** — 윈도우에 내장된 디스크 전체 암호화 기능으로, TPM 칩과 연동해 볼륨 단위로 저장 데이터를 보호하는 기능
  - 암호 알고리즘으로 AES 사용
- **솔트 (Salt)** — 비밀번호를 해시하기 전에 사용자마다 다른 임의 문자열을 덧붙여, 같은 비밀번호라도 서로 다른 해시값이 나오게 하는 값
  - 레인보 테이블 공격 대응책
- **키 스트레칭 (Key Stretching)** — 해시 연산을 수천 번 이상 반복 적용해 비밀번호 하나를 추측하는 데 드는 시간을 늘림으로써 무차별 대입을 어렵게 하는 기법
  - 예: PBKDF2, bcrypt, scrypt

## 서비스 거부 공격

- **DoS (Denial of Service)** — 대량의 요청이나 비정상 패킷으로 대상 시스템의 자원을 고갈시켜 정상 사용자가 서비스를 이용하지 못하게 하는 공격
- **DDoS (Distributed Denial of Service)** — 악성코드에 감염된 다수의 좀비 PC를 원격 조종해 여러 곳에서 동시에 한 대상에게 트래픽을 퍼붓는 공격
  - 구성: 공격자 → 핸들러(마스터) → 에이전트
- **트리누 (Trinoo)** — 마스터·에이전트 구조로 여러 호스트에서 동시에 UDP 플러드를 일으키는 초기의 분산 공격 도구
- **TFN (Tribe Flood Network)** — 트리누를 발전시킨 분산 공격 도구로, UDP·TCP SYN·ICMP 플러드와 스머프 공격 등을 골라 수행할 수 있는 도구
- **슈타헬드라트 (Stacheldraht)** — 독일어로 '철조망'을 뜻하는 분산 공격 도구로, 트리누와 TFN의 기능을 합치고 마스터·에이전트 간 통신을 암호화한 도구
- **죽음의 핑 (Ping of Death)** — 허용 최대 크기(65,535바이트)를 넘는 ICMP 에코 요청을 조각내 보내, 재조립 과정에서 대상 시스템을 멈추게 하는 공격
- **SYN 플러딩 (SYN Flooding)** — TCP 연결 요청 패킷만 대량으로 보내고 마지막 응답(ACK)은 주지 않아, 서버의 연결 대기 큐(백로그)를 가득 채우는 공격
- **스머프 (Smurf)** — 출발지를 공격 대상 IP로 위조한 ICMP 에코 요청을 네트워크 브로드캐스트 주소로 보내, 다수의 응답이 대상에게 몰리게 하는 공격
  - 대응: 라우터에서 다이렉트 브로드캐스트 차단
- **랜드 어택 (Land Attack)** — 출발지 IP와 목적지 IP를 모두 공격 대상의 주소로 같게 만든 패킷을 보내, 대상이 자기 자신에게 응답하며 루프에 빠지게 하는 공격
- **티어드롭 (Teardrop)** — IP 단편의 오프셋(Fragment Offset) 값을 겹치거나 어긋나게 조작해, 재조립 과정에서 대상 시스템이 오류를 일으키게 하는 공격
- **UDP 플러딩 (UDP Flooding)** — 대상의 임의 포트로 데이터그램을 대량으로 보내, 닫힌 포트마다 ICMP 도달 불가 응답을 반복하게 만들어 자원을 고갈시키는 공격

## 네트워크 공격

- **스니핑 (Sniffing)** — 네트워크를 지나가는 패킷을 몰래 엿들어 계정·비밀번호 같은 정보를 가로채는 수동적 공격
  - 랜카드를 무차별 모드(Promiscuous Mode)로 설정
- **스위치 재밍 (Switch Jamming)** — 위조한 MAC 주소를 대량으로 흘려 스위치의 주소 테이블을 넘치게 만들어, 스위치가 허브처럼 모든 포트로 프레임을 뿌리게 하는 공격
  - MAC 플러딩이라고도 함
- **IP 스푸핑 (IP Spoofing)** — 패킷의 출발지 주소를 신뢰받는 호스트의 것으로 위조해, 주소 기반 인증을 우회하거나 자신의 정체를 숨기는 공격
- **ARP 스푸핑 (ARP Spoofing)** — 같은 근거리 망에서 IP-MAC 대응 정보를 위조한 응답을 보내 피해자의 캐시를 오염시키고, 트래픽이 공격자를 거쳐 가게 만드는 공격
- **DNS 스푸핑 (DNS Spoofing)** — 도메인 이름 질의에 대한 응답을 위조하거나 캐시를 오염시켜, 사용자가 공격자가 만든 가짜 사이트로 접속하게 만드는 공격
- **APT (Advanced Persistent Threat)** — 특정 기관을 노리고 장기간 은밀히 잠복하며 침투 → 내부 확산 → 정보 탈취를 단계적으로 진행하는 표적 공격
- **세션 하이재킹 (Session Hijacking)** — 이미 인증을 마친 정상 사용자의 연결을 가로채, 시퀀스 번호나 세션 ID를 이용해 그 사용자인 척 통신을 이어 가는 공격

## 애플리케이션 공격

- **SQL 인젝션 (SQL Injection)** — 입력란에 데이터베이스 질의문 조각을 끼워 넣어 인증을 우회하거나 데이터를 무단으로 조회·변조하는 공격
  - 대응: 바인딩 변수(Prepared Statement), 입력값 검증
- **XSS (Cross-Site Scripting)** — 게시판 등에 악성 코드(자바스크립트 등)를 심어 두어, 그 페이지를 연 다른 사용자의 브라우저에서 실행되게 하고 쿠키·세션을 빼내는 공격
  - 유형: 저장형, 반사형, DOM 기반
- **CSRF (Cross-Site Request Forgery)** — 로그인한 사용자가 모르는 사이에 공격자가 의도한 요청(송금·정보 변경 등)을 그 사용자의 권한으로 서버에 보내게 만드는 공격
- **레인보 테이블 공격 (Rainbow Table Attack)** — 평문과 해시값의 대응을 체인 형태로 미리 계산해 압축 저장한 표를 써서, 탈취한 비밀번호 해시의 원래 값을 빠르게 찾아내는 공격
  - 대응: 솔트

## 사람과 사이트를 노리는 공격

- **사회 공학 (Social Engineering)** — 기술적 취약점 대신 사람의 신뢰·호기심·두려움을 이용해 속여서 비밀번호 같은 정보나 접근 권한을 얻어 내는 공격 기법
- **워터링 홀 (Watering Hole)** — 공격 대상 집단이 자주 드나드는 웹사이트를 미리 감염시켜 두고, 그 사이트에 들어온 사람에게 악성코드를 퍼뜨리는 공격
- **타이포스쿼팅 (Typosquatting)** — 주소를 잘못 입력하는 실수를 노려, 유명 사이트와 철자가 한두 글자 다른 도메인을 등록해 두고 가짜 사이트로 유인하는 공격

## 블루투스 공격

- **블루버그 (BlueBug)** — 블루투스 기기의 취약점을 이용해 인증 없이 원격으로 기기를 장악하고, 통화·문자 발송 같은 명령까지 실행하는 공격
- **블루스나프 (BlueSnarf)** — 블루투스 파일 교환 프로토콜(OBEX)의 취약점을 이용해 허락 없이 기기 안의 주소록·일정·파일 등을 빼내는 공격
- **블루재킹 (BlueJacking)** — 근처의 블루투스 기기에 명함 전송 기능 등을 이용해 원치 않는 메시지·스팸을 일방적으로 보내는 공격
- **블루프린팅 (BluePrinting)** — 공격 대상이 될 블루투스 기기를 찾아 기기 종류·모델·제공 서비스 같은 정보를 수집하는 사전 정찰 공격

## 보안 솔루션

- **IDS (Intrusion Detection System)** — 네트워크·호스트의 활동을 감시하다가 알려진 공격 패턴이나 비정상 행위를 발견하면 관리자에게 경보를 보내는 시스템
  - 판별 기법: 오용(시그니처) 기반, 이상(행위) 기반
- **IPS (Intrusion Prevention System)** — 공격 징후를 실시간으로 찾아내 경보에 그치지 않고 해당 트래픽을 자동으로 차단까지 하는 능동형 시스템
- **방화벽 (Firewall)** — 내부망과 외부망 경계에서 미리 정한 규칙(IP·포트·프로토콜 등)에 따라 트래픽의 통과와 차단을 결정하는 시스템
- **VPN (Virtual Private Network)** — 인터넷 같은 공중망 위에 암호화된 터널을 만들어 마치 전용선처럼 안전하게 통신하게 하는 기술
  - 구현 프로토콜: IPSec, SSL/TLS, PPTP, L2TP
- **DLP (Data Loss Prevention)** — 조직 내부의 중요 정보가 메일·USB·출력물 등을 통해 외부로 새어 나가는 것을 감시하고 차단하는 솔루션
- **허니팟 (Honeypot)** — 일부러 취약하게 보이도록 꾸민 미끼 시스템으로, 공격자를 끌어들여 그 행동을 관찰·기록하는 시스템
- **NAC (Network Access Control)** — 단말이 내부망에 붙기 전에 백신 설치·패치 상태 등 보안 정책 준수 여부를 검사해 접속을 허용하거나 격리하는 솔루션
- **ESM (Enterprise Security Management)** — 방화벽·IDS·IPS 등 여러 보안 장비의 로그와 이벤트를 한곳에 모아 통합 관리·분석하는 솔루션
- **SIEM (Security Information and Event Management)** — 여러 장비·서버의 로그를 빅데이터 기반으로 수집하고 상관 분석해 위협을 실시간으로 찾아내고 대응하는 솔루션
  - ESM의 발전형

## 인증·보안 관리 체계

- **AAA (Authentication, Authorization, Accounting)** — 네트워크에 접속하는 사용자의 신원 확인, 권한 부여, 사용 내역 기록의 세 가지를 한 서버에서 처리하는 보안 체계
  - 대표 프로토콜: RADIUS, TACACS+, Diameter
- Q: AAA의 세 기능 중 사용자가 무엇을 얼마나 썼는지 기록해 과금·감사에 쓰는 기능은? — Accounting (계정 관리)
- **ISMS (Information Security Management System)** — 조직이 정보 자산을 지키려고 세운 정책·조직·절차·대책이 기준에 맞게 운영되는지 심사해 인증하는 국내 정보보호 관리체계 인증 제도
- **트러스트존 (TrustZone)** — ARM 프로세서가 한 칩 안을 일반 영역과 격리된 보안 영역으로 나눠, 결제·생체 정보 같은 민감한 처리를 보안 영역에서만 하게 하는 하드웨어 기술

## 보안 프로토콜

- **SSH (Secure Shell)** — 원격 접속(텔넷 대체)과 파일 전송 때 오가는 모든 데이터를 암호화하는 프로토콜로, 기본 포트는 22번
- **SSL (Secure Sockets Layer) / TLS (Transport Layer Security)** — TCP 위에서 동작하며 웹 통신 등에 서버 인증·암호화·무결성을 제공하는 프로토콜로, 넷스케이프의 원형을 IETF가 표준화한 후속판이 있다
  - HTTPS 기본 포트 443
- **S-HTTP (Secure HTTP)** — 웹에서 주고받는 메시지(문서) 하나하나에 암호화와 서명을 적용하는 프로토콜로, 통신 채널 전체를 보호하는 방식과 구별된다
- **IPSec (IP Security)** — 네트워크 계층(3계층)에서 패킷 단위로 인증과 암호화를 제공하는 프로토콜 모음으로, VPN 구현에 널리 쓰인다
- **IPSec 전송 모드 (Transport Mode)** — 원래 IP 헤더는 그대로 두고 페이로드만 보호하는 방식으로, 종단 호스트끼리 직접 통신할 때 쓴다
- **IPSec 터널 모드 (Tunnel Mode)** — 원래 IP 패킷 전체를 보호한 뒤 새 IP 헤더를 덧붙이는 방식으로, 게이트웨이 간 VPN 구성에 쓴다
- **AH (Authentication Header)** — 패킷의 무결성과 출발지 인증을 제공하지만 암호화는 하지 않는 IPSec 구성 프로토콜
- **ESP (Encapsulating Security Payload)** — 패킷 내용을 암호화해 기밀성을 제공하고 선택적으로 무결성·출발지 인증까지 제공하는 IPSec 구성 프로토콜
- **IKE (Internet Key Exchange)** — IPSec 통신 양측이 보안 연관(SA)과 암호 키를 자동으로 협상·생성하도록 해 주는 프로토콜
  - UDP 500번 포트 사용
- **TKIP (Temporal Key Integrity Protocol)** — 무선랜의 WEP 약점을 보완하려고 만든 암호 프로토콜로, 패킷마다 키를 바꿔 쓰고 메시지 무결성 검사를 더했다. WPA에서 쓰였다

## DRM 구성요소

- **DRM (Digital Rights Management)** — 디지털 콘텐츠의 불법 복제를 막고 허가된 사용자만 정해진 권한 범위 안에서 이용하도록 통제하는 기술
- **콘텐츠 제공자 (Contents Provider)** — 콘텐츠를 직접 만들거나 저작권을 보유하고 있어 보호 대상 콘텐츠를 공급하는 주체
- **콘텐츠 분배자 (Contents Distributor)** — 온라인 쇼핑몰처럼 암호화 등 보호 처리를 거친 콘텐츠를 최종 사용자에게 유통하고 판매하는 주체
- **패키저 (Packager)** — 원본 콘텐츠에 이용 조건 같은 부가 정보를 붙이고 암호화해, 유통할 수 있는 보호 파일로 만들어 내는 도구
- **보안 컨테이너 (Security Container)** — 원본 콘텐츠와 이용 규칙을 함께 감싸 담아 유통 과정에서 무단 접근을 막는 전자적 보안 장치
- **DRM 컨트롤러 (DRM Controller)** — 사용자 단말에서 배포된 콘텐츠의 이용 권한을 확인하고 재생·복사 등 사용을 통제하는 프로그램
- **클리어링 하우스 (Clearing House)** — 암호 키 관리와 라이선스 발급, 사용량에 따른 결제 정산을 담당하는 주체

## 사후 대응

- **디지털 포렌식 (Digital Forensics)** — 컴퓨터·저장 매체에 남은 전자적 흔적을 수집·보존·분석해 법정에서 증거로 쓸 수 있게 만드는 과학적 조사 기법
  - 원칙: 정당성, 재현성, 신속성, 연계 보관성, 무결성
