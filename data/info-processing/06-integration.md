# 통합 구현 · 인터페이스 구현

## 연계 데이터 형식

- **XML (eXtensible Markup Language)** — 사용자가 태그를 직접 정의해 데이터를 트리 구조로 기술하는 확장형 마크업 언어. DTD나 스키마로 문서 구조를 검증할 수 있는 것
- **JSON (JavaScript Object Notation)** — 이름과 값의 쌍, 배열로 데이터를 나타내는 가벼운 텍스트 형식. 자바스크립트 객체 문법에서 나왔지만 특정 언어에 묶이지 않는 것
- **CSV (Comma-Separated Values)** — 한 행을 한 줄로 두고 필드를 쉼표로 나누어 표 형태 데이터를 담는 가장 단순한 텍스트 형식
- **AJAX (Asynchronous JavaScript and XML)** — 페이지 전체를 새로 불러오지 않고 브라우저가 서버와 비동기로 데이터를 주고받아 화면 일부만 갱신하는 웹 기법
- **REST (Representational State Transfer)** — URI로 자원을 식별하고 HTTP 메서드로 그 자원에 대한 행위를 표현하는 무상태 기반 웹 아키텍처 스타일
- Q: REST에서 CRUD 연산과 짝을 이루는 HTTP 메서드는? — Create = POST, Read = GET, Update = PUT, Delete = DELETE

## 웹 서비스 구성 요소

- **SOAP (Simple Object Access Protocol)** — HTTP 같은 전송 프로토콜 위에서 Envelope·Header·Body로 이루어진 XML 메시지로 원격 서비스를 호출하는 통신 규약
- **WSDL (Web Services Description Language)** — 서비스가 제공하는 기능, 주고받는 메시지 형식, 접근 위치와 프로토콜을 XML로 기술한 명세 언어
- **UDDI (Universal Description, Discovery and Integration)** — 제공자가 서비스 정보를 등록하고 요청자가 원하는 서비스를 검색해 찾아 쓰게 하는 레지스트리(저장소) 규격

## EAI 구축 유형

- **EAI (Enterprise Application Integration)** — 기업 안의 이기종 응용 시스템들을 미들웨어로 엮어 데이터와 업무 프로세스를 함께 쓰게 하는 연계 솔루션
- **Point-to-Point** — 미들웨어 없이 애플리케이션끼리 1:1로 직접 잇는 가장 단순한 유형. 시스템이 늘면 연결 수가 급증하고 재사용이 어려운 것
- **Hub & Spoke** — 중앙 중계 시스템이 모든 시스템 간 데이터 전달을 맡는 집중형 유형. 관리·확장은 쉽지만 중앙이 단일 장애점이 되는 것
- **Message Bus** — 애플리케이션 사이에 미들웨어 계층을 두고 그 위로 메시지를 흘려 보내는 유형. 확장성이 뛰어나 대용량 처리에 적합한 것
- **Hybrid** — 그룹 내부는 중앙 집중형으로, 그룹 사이는 미들웨어 계층형으로 묶는 혼합 유형. 필요한 방식을 골라 적용해 병목을 줄이는 것

## ESB

- **ESB (Enterprise Service Bus)** — 애플리케이션이 아니라 서비스 단위로 연계하며, 표준 기반 통신 기반 위에서 메시지 변환·라우팅을 맡는 미들웨어. SOA 구현의 토대가 되는 것
- Q: EAI와 ESB의 차이는? — EAI는 기업 내부 애플리케이션 간 통합에 초점(상대적으로 강한 결합), ESB는 서비스 중심 통합에 초점(느슨한 결합, 표준 기반으로 SOA 지원)

## 연계 기술

> 직접 연계: 중간 매개체 없이 시스템끼리 바로 연결 / 간접 연계: 연계 솔루션(EAI·ESB)이나 소켓을 거쳐 연결

- **DB Link** — 원격 데이터베이스를 가리키는 객체를 만들어 두고 `테이블명@객체명` 형식으로 원격 테이블을 직접 조회하는 직접 연계 방식
- **DB Connection (Pool)** — 애플리케이션 서버(WAS)가 데이터베이스 접속 객체를 미리 여러 개 만들어 두고 꺼내 쓰고 반납하는 직접 연계 방식. 접속 생성 비용을 줄이는 것
- **API (Application Programming Interface) / Open API** — 다른 시스템의 데이터나 기능을 정해진 호출 규약대로 프로그램에서 쓰게 하는 인터페이스. 누구나 쓰도록 공개한 형태도 있는 것
- **JDBC (Java Database Connectivity)** — 자바 프로그램이 드라이버를 거쳐 여러 관계형 DB에 접속하고 SQL을 실행하게 해 주는 표준 인터페이스
- **Hyper Link** — 웹 화면에 다른 시스템의 페이지 주소를 걸어 사용자가 클릭으로 바로 이동하게 하는 가장 단순한 직접 연계 방식
- **연계 솔루션 (간접 연계)** — 송·수신 시스템 사이에 EAI·ESB 같은 중계 솔루션을 두어 데이터 변환과 라우팅을 맡기는 방식. 이기종 연계에 유리하나 구성이 복잡한 것
- **소켓 (Socket, 간접 연계)** — 통신용 포트를 열어 두고 송·수신 측이 연결을 맺어 데이터를 주고받게 하는 간접 연계 수단. 서버-클라이언트 통신의 기본이 되는 것

## DB 접근 기술

- **ODBC (Open Database Connectivity)** — 마이크로소프트가 정한 표준 규격으로, 응용 프로그램이 DBMS 종류와 상관없이 같은 방법으로 데이터베이스에 접근하게 하는 인터페이스
- **ORM (Object-Relational Mapping)** — 프로그램의 클래스(객체)와 관계형 DB의 테이블을 자동으로 대응시켜 SQL을 직접 쓰지 않고 객체로 데이터를 다루게 하는 기법
  - 예: JPA/Hibernate, SQLAlchemy

> JDBC는 위 「연계 기술」 그룹 참고

## 인터페이스 구현 검증 도구

- **xUnit** — JUnit·NUnit·CppUnit처럼 언어마다 만들어진, 같은 구조의 단위 테스트 프레임워크들을 한데 묶어 부르는 이름
- **JUnit** — 자바 언어 전용 단위 테스트 프레임워크로, 테스트용 애노테이션을 붙인 메서드를 자동 실행하고 기대값과 실제값을 단언문(assert)으로 비교한다
- **STAF (Software Testing Automation Framework)** — 여러 플랫폼과 분산 환경을 지원하는 테스트 자동화 프레임워크. 테스트 대상마다 데몬을 띄워 원격으로 테스트를 실행하고 결과를 모으는 것
- **FitNesse** — 웹 기반 위키 페이지에 입력값과 기대 결과를 표로 적으면 그대로 실행되는 테스트 프레임워크. 비개발자도 테스트 케이스를 쓸 수 있는 것
- **NTAF (Naver Test Automation Framework)** — NHN이 만든 테스트 자동화 프레임워크로, STAF의 재사용·확장성과 FitNesse의 협업 기능을 합친 것
- **Selenium** — 브라우저를 코드로 자동 조작해 웹 화면의 동작을 검증하는 오픈소스 도구. 크롬·파이어폭스 등 여러 브라우저와 Java·Python 등 여러 언어로 쓸 수 있다
- **Watir (Web Application Testing in Ruby)** — 루비로 테스트 스크립트를 작성해 실제 웹 브라우저를 자동 조작하는 웹 애플리케이션 테스트 도구

## 데이터베이스 암호화 방식

> SSL/TLS·IPSec·S-HTTP 등 인터페이스 보안 프로토콜은 보안 과목에서 다룬다

- **API 방식** — 애플리케이션 단에서 암·복호화 라이브러리를 호출해 처리하는 방식. DB 서버 부하는 없지만 애플리케이션 코드를 고쳐야 하는 것
- **Plug-in 방식** — DB 서버에 암·복호화 모듈을 설치하고 DB 함수(뷰·트리거 등)로 처리하는 방식. 애플리케이션 수정은 적지만 DB 서버에 부하가 걸리는 것
- **TDE (Transparent Data Encryption) 방식** — DBMS 커널 수준에서 저장할 때 암호화하고 읽을 때 복호화해 애플리케이션이 알아채지 못하게 하는 방식. 코드 수정이 거의 없는 것
- **Hybrid 방식** — 애플리케이션 측 처리와 DB 서버 측 모듈 처리를 결합해 각각의 장점을 취하고 부하를 나누는 방식
