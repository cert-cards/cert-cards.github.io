# 화면 설계

## UI·UX

- **UI (User Interface)** — 사용자와 시스템이 정보를 주고받도록 이어 주는 화면·버튼·메뉴 같은 접점 요소. 눈에 보이는 상호작용 수단에 초점을 둔다.
- **UX (User Experience)** — 사용자가 시스템을 이용하면서 느끼고 생각하는 총체적인 경험. 만족도·감성·편의성 같은 주관적 인상까지 포함한다.

## UI 유형

- **CLI (Command Line Interface)** — 사용자가 키보드로 명령어 문자열을 입력해 시스템을 조작하는 텍스트 기반 방식.
  - 예: 터미널, 셸
- **GUI (Graphical User Interface)** — 아이콘·창·메뉴 같은 그래픽 요소를 마우스 등 포인팅 장치로 선택해 조작하는 방식.
- **NUI (Natural User Interface)** — 별도의 입력 장치 없이 말, 손짓, 터치처럼 사람의 자연스러운 행동으로 기기를 조작하는 방식.
- **OUI (Organic User Interface)** — 모든 사물과 표면이 입출력 장치가 될 수 있다는 개념으로, 형태가 바뀌는 디스플레이처럼 사물 자체가 사용자와 상호작용하는 방식.

## UI 설계 원칙 (직유학유)

- **직관성 (Intuitiveness)** — 사용자가 따로 배우거나 설명을 듣지 않아도 쉽게 이해하고 바로 사용할 수 있어야 한다는 원칙.
- **유효성 (Effectiveness)** — 사용자가 달성하려는 목적을 정확하고 완전하게 이룰 수 있도록 설계해야 한다는 원칙.
- **학습성 (Learnability)** — 초보자와 숙련자 모두 사용법을 쉽게 배우고 오래 기억할 수 있어야 한다는 원칙.
- **유연성 (Flexibility)** — 사용자의 다양한 요구를 최대한 받아들이고 실수를 막거나 쉽게 되돌릴 수 있어야 한다는 원칙.

## UI 설계 도구

- **와이어프레임 (Wireframe)** — 화면에 들어갈 요소의 대략적인 위치와 배치를 선과 상자로 간단히 그린 설계도. 색과 디자인은 생략한다.
- **목업 (Mockup)** — 실제 화면과 거의 같은 수준으로 시각적 디자인까지 정적으로 구현한 모형. 실제로 동작하는 기능은 없다.
- **스토리보드 (Storyboard)** — 화면 설계안에 정책·프로세스·콘텐츠 구성·기능 설명 등을 함께 정리한 문서로, 디자이너와 개발자가 최종적으로 참고하는 산출물.
- **프로토타입 (Prototype)** — 화면 설계에 클릭·화면 전환 같은 실제와 비슷한 상호작용을 넣어 동작을 직접 확인할 수 있게 만든 동적 견본.
  - 종류: 페이퍼, 디지털
- **유스케이스 (Use Case)** — 사용자 관점에서 시스템이 제공해야 할 기능을 사용자와 시스템 사이의 상호작용 시나리오로 표현한 것. 액터와 기능의 관계를 다이어그램으로 나타낸다.

## UI 시나리오 문서 작성 요건 (완일이가추수)

- **완전성 (Complete)** — 사용자의 모든 작업 흐름과 시스템 기능을 하나도 빠뜨리지 않고 기술해야 한다는 요건.
- **일관성 (Consistent)** — 서비스 목표, 시스템·사용자 요구사항, 용어와 표현이 문서 전체에서 서로 어긋나지 않아야 한다는 요건.
- **이해성 (Understandable)** — 처음 읽는 사람도 쉽게 이해할 수 있도록 모호하거나 추상적인 표현을 피해야 한다는 요건.
- **가독성 (Readable)** — 목차·문단·글꼴·여백·도식을 활용해 쉽게 읽히고 원하는 내용을 빨리 찾을 수 있도록 작성해야 한다는 요건.
- **추적 용이성 (Traceable)** — 무엇이 언제, 어느 부분에서, 왜 바뀌었는지 변경 이력을 쉽게 따라가 확인할 수 있어야 한다는 요건.
- **수정 용이성 (Modifiable)** — 내용을 바꿀 때 같은 내용을 여러 곳에서 고칠 필요가 없도록 구성해 변경이 쉬워야 한다는 요건.
