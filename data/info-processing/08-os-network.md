# 운영체제 · 네트워크

## 프로세스

- **프로세스 (Process)** — 실행 중인 프로그램으로, 운영체제로부터 CPU·메모리 등 자원을 할당받아 동작하는 작업 단위
- **스레드 (Thread)** — 프로세스 안에서 실행되는 흐름의 단위. 같은 프로세스 안에서 코드·데이터·자원은 공유하고 스택과 레지스터는 따로 갖는 것
- Q: 프로세스 상태 전이의 기본 흐름은? — 생성(New) → 준비(Ready) → 실행(Running) → 종료(Terminated). 실행 중 입출력을 요청하면 대기(Waiting/Blocked)로 갔다가 준비로 돌아온다
- **디스패치 (Dispatch)** — 준비 상태의 프로세스 중 하나를 스케줄러가 골라 CPU를 넘겨 실행 상태로 옮기는 전이
- Q: 실행 → 준비 전이(할당 시간 만료)의 이름은? — 타임아웃 (Timeout, 타이머 런아웃)
- Q: 실행 → 대기 전이(입출력 요청)의 이름은? — 블록 (Block)
- Q: 대기 → 준비 전이(입출력 완료)의 이름은? — 웨이크업 (Wake Up)
- **문맥 교환 (Context Switching)** — CPU를 다른 프로세스에 넘길 때 현재 레지스터 등 실행 상태를 저장하고 다음 프로세스의 상태를 복원하는 과정. 잦으면 오버헤드가 커지는 것
- **PCB (Process Control Block)** — 운영체제가 프로세스마다 두는 자료 구조로, 식별자·상태·프로그램 카운터·레지스터·스케줄링·메모리 정보를 담는 것

## 선점형 스케줄링

> 선점형: 실행 중인 프로세스에게서 운영체제가 CPU를 빼앗아 다른 프로세스에 줄 수 있는 방식

- **SRT (Shortest Remaining Time)** — 남은 실행 시간이 가장 짧은 프로세스에 CPU를 주고, 더 짧은 작업이 도착하면 실행 중인 것을 중단시키고 넘겨주는 방식
- **라운드 로빈 (Round Robin)** — 도착 순서대로 CPU를 주되 정해진 시간 할당량만큼만 실행하고, 끝나지 않으면 준비 큐 맨 뒤로 보내는 시분할용 방식
- **다단계 큐 (Multi-Level Queue, MLQ)** — 프로세스를 성격(시스템·대화형·일괄 처리 등)별로 우선순위가 다른 여러 큐에 고정 배치하고 큐마다 다른 스케줄링을 쓰는 방식. 큐 사이 이동이 없는 것
- **다단계 피드백 큐 (Multi-Level Feedback Queue, MLFQ)** — 여러 우선순위 큐를 두고 할당 시간을 다 쓴 프로세스는 아래 큐로 내려 큐 사이를 옮기는 방식. 아래 큐일수록 할당 시간이 길고 마지막 큐는 순환 할당인 것

## 비선점형 스케줄링

> 비선점형: 한 번 CPU를 받은 프로세스가 끝나거나 스스로 내놓을 때까지 빼앗지 않는 방식

- **FCFS (First Come First Served)** — 준비 큐에 먼저 도착한 프로세스부터 끝날 때까지 CPU를 주는 방식. 긴 작업 뒤의 짧은 작업이 오래 기다리는 호위 효과가 생기는 것
- **SJF (Shortest Job First)** — 실행 시간이 가장 짧은 프로세스부터 처리하는 방식. 평균 대기 시간은 최소지만 긴 작업이 계속 밀릴 수 있는 것
- **HRN (Highest Response-ratio Next)** — 대기 시간과 서비스 시간을 함께 따져 응답률이 가장 높은 프로세스를 먼저 실행하는 방식. 짧은 작업 편중과 무기한 대기를 완화하는 것
- Q: HRN의 우선순위 계산식은? — (대기 시간 + 서비스 시간) ÷ 서비스 시간
  - 값이 클수록 먼저 실행
- **기한부 (Deadline)** — 각 작업에 마감 시각을 정해 주고 그 안에 끝내도록 계획하는 방식. 시간 계산 오버헤드가 크고 마감을 넘기면 작업 가치가 떨어지는 것
- **우선순위 (Priority)** — 프로세스마다 중요도 값을 매겨 그 값이 가장 높은 것부터 CPU를 주는 방식. 낮은 쪽은 무기한 대기에 빠질 수 있는 것

## 기아 · 에이징

- **기아 현상 (Starvation)** — 우선순위가 낮거나 실행 시간이 긴 프로세스가 자원을 계속 받지 못하고 무기한 기다리는 상태
- **에이징 (Aging)** — 오래 기다린 프로세스일수록 우선순위를 조금씩 올려 무기한 대기를 막는 기법

## 동기화 · 통신

- **임계 구역 (Critical Section)** — 여러 프로세스가 공유하는 자원에 접근하는 코드 영역으로, 한 번에 하나의 프로세스만 들어가야 하는 부분
- **상호 배제 (Mutual Exclusion)** — 한 프로세스가 공유 자원을 쓰는 동안 다른 프로세스가 같은 자원에 접근하지 못하게 막는 것
- **세마포어 (Semaphore)** — 정수 변수와 두 개의 원자적 연산으로 공유 자원 접근을 제어하는 동기화 도구. 다익스트라가 제안한 것
- Q: 세마포어의 두 연산은? — P 연산(wait: 값이 0보다 크면 1 감소, 아니면 대기)과 V 연산(signal: 1 증가 후 대기 중인 프로세스를 깨움)
- **교착 상태 (Deadlock)** — 둘 이상의 프로세스가 서로 상대가 가진 자원을 기다리며 아무도 진행하지 못하는 상태
  - 필요 조건: 상호 배제·점유와 대기·비선점·환형 대기
- **IPC (Inter-Process Communication)** — 독립된 프로세스들이 데이터를 주고받거나 동작을 맞추도록 운영체제가 제공하는 통신 수단
  - 파이프·메시지 큐·공유 메모리·소켓·시그널·세마포어

## 운영체제 구성 · 종류

- **커널 (Kernel)** — 운영체제의 핵심으로 메모리에 상주하며 프로세스·메모리·파일·입출력 등 하드웨어 자원을 직접 관리하는 부분
- **셸 (Shell)** — 사용자가 입력한 명령을 해석해 핵심부에 전달하는 명령어 해석기. 사용자와 운영체제 핵심부 사이의 인터페이스인 것
- **유닉스 (UNIX)** — 벨 연구소에서 만들어 대부분 C 언어로 다시 작성된 다중 사용자·다중 작업 운영체제. 이식성이 높고 계층적 파일 시스템을 갖는 것
- **리눅스 (Linux)** — 리누스 토르발스가 유닉스 호환으로 만든 오픈 소스 운영체제 커널. 누구나 소스를 고치고 배포할 수 있는 것
- **안드로이드 (Android)** — 리눅스 커널 위에 구글이 만든 모바일 운영체제. 소스가 공개되어 여러 제조사가 쓰며, 앱은 주로 자바·코틀린으로 개발한다
- Q: 리눅스에서 `chmod 754 파일명`을 실행하면 부여되는 권한은? — 소유자 rwx · 그룹 r-x · 기타 r--
  - r=4, w=2, x=1을 더한 숫자를 소유자·그룹·기타 순으로 쓴다

## OSI 7계층 (물데네전세표응)

- **물리 계층 (Physical Layer)** — 전송 매체의 전기·기계·기능적 특성을 정해 비트 신호를 실어 보내는 1계층
  - 단위: 비트 / 장비: 리피터·허브
- **데이터 링크 계층 (Data Link Layer)** — 인접 노드 사이의 프레임 전달을 맡고 MAC 주소로 흐름·오류 제어를 하는 2계층
  - 단위: 프레임 / 장비: 브리지·스위치 / HDLC·PPP·이더넷
- **네트워크 계층 (Network Layer)** — 논리 주소(IP)로 여러 망을 거치는 최적 경로를 찾아 목적지까지 전달하는 3계층
  - 단위: 패킷 / 장비: 라우터 / IP·ARP·ICMP·IGMP
- **전송 계층 (Transport Layer)** — 포트 번호로 종단 프로세스 간 신뢰성 있는 전달을 맡고 분할·재조립·흐름·오류 제어를 하는 4계층
  - 단위: 세그먼트 / TCP·UDP
- **세션 계층 (Session Layer)** — 통신하는 양 끝의 대화를 수립·유지·종료하고 동기점(체크포인트)을 두어 대화를 관리하는 5계층
- **표현 계층 (Presentation Layer)** — 서로 다른 데이터 형식을 쓰는 시스템이 이해할 수 있도록 코드 변환·암호화·압축을 맡는 6계층
  - JPEG·MPEG·ASCII
- **응용 계층 (Application Layer)** — 사용자 프로그램이 망 서비스에 접근하도록 창구를 제공하는 최상위 7계층
  - HTTP·FTP·SMTP·DNS·TELNET·SNMP

## 프로토콜

- **프로토콜 (Protocol)** — 서로 다른 시스템이나 장비가 데이터를 주고받기 위해 미리 합의해 둔 통신 규약

## 프로토콜 기본 요소 (구의타)

- **구문 (Syntax)** — 기본 요소 중 데이터의 형식, 부호화 방법, 신호 수준을 정한 것
- **의미 (Semantics)** — 기본 요소 중 전송 제어와 오류 처리를 위한 제어 정보를 정한 것
- **타이밍 (Timing)** — 기본 요소 중 통신 속도를 맞추고 메시지 순서를 제어하는 것

## 네트워크 계층 프로토콜

- **IP (Internet Protocol)** — 패킷에 출발지·목적지 논리 주소를 붙여 경로를 따라 넘기는 비연결형 프로토콜. 도착을 보장하지 않는 최선 노력 방식인 것
- **ARP (Address Resolution Protocol)** — IP 주소를 알 때 그에 대응하는 물리(MAC) 주소를 알아내는 프로토콜
- **RARP (Reverse Address Resolution Protocol)** — 자신의 물리(MAC) 주소를 근거로 서버에 물어 자기 IP 주소를 얻어내는 프로토콜
- **ICMP (Internet Control Message Protocol)** — IP 패킷 처리 중 생긴 오류나 상태 정보를 송신 측에 알리는 프로토콜
  - ping·traceroute가 이용
- **IGMP (Internet Group Management Protocol)** — 호스트와 라우터 사이에서 멀티캐스트 수신 집단의 가입·탈퇴 정보를 관리하는 프로토콜
- **IPv4 (Internet Protocol version 4)** — 32비트 주소를 8비트씩 넷으로 나눠 점으로 구분한 10진수로 표기하는 주소 체계. A~E 클래스로 나뉘는 것
  - 예: 192.168.0.1
- **IPv6 (Internet Protocol version 6)** — 주소 고갈을 풀려고 만든 128비트 주소 체계. 16비트씩 여덟 부분을 콜론으로 구분한 16진수로 쓰고 보안·자동 구성을 강화한 것

## IPv4 / IPv6 전환 기술

- **듀얼 스택 (Dual Stack)** — 한 호스트나 라우터에 두 버전의 프로토콜을 모두 탑재해 통신 상대에 따라 골라 쓰는 방식
- **터널링 (Tunneling)** — IPv6 패킷을 IPv4 패킷 안에 캡슐화해 IPv4 망을 통과시키는(또는 그 반대) 방식
- **주소 변환 · 헤더 변환 (Header Translation)** — 중간 장비가 패킷 머리 정보를 상대 버전 형식으로 고쳐 써서 서로 다른 버전의 호스트끼리 통신하게 하는 방식

## 전송 방식

- **유니캐스트 (Unicast)** — 송신자 하나가 특정 수신자 하나에게 보내는 1:1 방식. IPv4·IPv6 모두 사용
- **멀티캐스트 (Multicast)** — 송신자 하나가 가입한 특정 집단의 구성원들에게만 보내는 1:N 방식. IPv4·IPv6 모두 사용
- **브로드캐스트 (Broadcast)** — 같은 망 안의 모든 호스트에게 한꺼번에 보내는 방식. IPv4에만 있고 IPv6에서는 1:N 집단 전송으로 대체된 것
- **애니캐스트 (Anycast)** — 같은 주소를 가진 여러 노드 중 경로상 가장 가까운 하나에게만 보내는 방식. IPv6가 주소 유형으로 정의한 것

## 전송 계층 프로토콜

- **TCP (Transmission Control Protocol)** — 3-way 핸드셰이크로 연결을 맺고 순서 보장·재전송·흐름 제어·혼잡 제어로 신뢰성 있게 전달하는 연결 지향 프로토콜
- **UDP (User Datagram Protocol)** — 연결 설정과 확인 응답 없이 보내는 비연결형 프로토콜. 신뢰성은 낮지만 헤더가 작고 빨라 실시간 스트리밍·DNS 질의에 쓰이는 것
- **소켓 (Socket)** — IP 주소와 포트 번호를 묶어 프로세스 간 통신의 끝점을 나타내는 소프트웨어 인터페이스. 응용 프로그램이 전송 계층을 쓰는 창구인 것

## 라우팅 프로토콜

- **IGP (Interior Gateway Protocol)** — 하나의 자율 시스템(AS) 안에서 라우팅 정보를 교환하는 프로토콜 계열
  - RIP·OSPF
- **RIP (Routing Information Protocol)** — 거리 벡터(벨만-포드) 알고리즘으로 홉 수가 가장 적은 경로를 고르는 내부 라우팅 프로토콜. 최대 홉 15라 소규모 망용이고 30초마다 갱신하는 것
- **OSPF (Open Shortest Path First)** — 링크 상태(다익스트라) 알고리즘으로 망 전체 구조를 파악해 최적 경로를 계산하는 내부 라우팅 프로토콜. 대규모 망에 적합하고 변화가 생기면 즉시 전파하는 것
- **EGP (Exterior Gateway Protocol)** — 서로 다른 자율 시스템(AS) 사이에서 라우팅 정보를 주고받는 프로토콜 계열(또는 그 초기 프로토콜)
  - 대표: BGP
- **BGP (Border Gateway Protocol)** — 자율 시스템 사이에서 경로 벡터 방식으로 경로를 교환하는 외부 라우팅 프로토콜. ISP 간 인터넷 백본에 쓰이고 TCP 179번을 쓰는 것

## 네트워크 장비

- **리피터 (Repeater)** — 약해진 신호를 증폭·재생해 전송 거리를 늘리는 1계층(물리) 장비
- **허브 (Hub)** — 여러 장비를 한곳에 모아 연결하고 받은 신호를 모든 포트로 내보내는 1계층 장비. 연결된 장비들이 대역폭을 나눠 쓰는 것
- **브리지 (Bridge)** — MAC 주소를 보고 두 LAN 구간을 이어 프레임을 걸러 전달하는 2계층 장비. 충돌 도메인을 나누는 것
- **스위치 (Switch)** — MAC 주소 테이블로 목적지 포트에만 프레임을 보내는 2계층 장비. 하드웨어 처리라 빠르고 포트마다 전용 대역폭을 주는 것
  - L3·L4·L7 제품도 있음
- **라우터 (Router)** — IP 주소를 보고 서로 다른 망을 이어 최적 경로로 패킷을 전달하는 3계층 장비. 브로드캐스트 도메인을 나누는 것
- **게이트웨이 (Gateway)** — 프로토콜 구조가 전혀 다른 망끼리 잇기 위해 프로토콜 변환을 해 주는 장비. 주로 4~7계층(전 계층)을 다루는 것

## LAN · 매체 접근 제어

- **LAN (Local Area Network)** — 건물·캠퍼스처럼 한정된 지역 안의 장비들을 고속·저오류로 묶는 망. 버스·링·스타형 토폴로지를 쓰는 것
- **이더넷 (Ethernet)** — 버스·스타형 구성에서 충돌 감지 방식으로 매체 접근을 제어하는 가장 널리 쓰이는 유선 LAN 기술. IEEE 802.3 표준인 것
- **CSMA/CD (Carrier Sense Multiple Access with Collision Detection)** — 보내기 전에 회선이 비었는지 살피고, 보내다 충돌을 감지하면 멈춘 뒤 임의 시간 후 다시 보내는 유선 LAN 매체 접근 방식
- **CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance)** — 충돌 감지가 어려운 무선 LAN에서 채널이 비어도 임의 대기 시간을 둔 뒤 보내 충돌을 미리 피하는 매체 접근 방식
  - RTS/CTS 사용 가능
- Q: IEEE 802.3은? — CSMA/CD (이더넷, 유선 LAN)
- Q: IEEE 802.4는? — 토큰 버스 (Token Bus)
- Q: IEEE 802.5는? — 토큰 링 (Token Ring)
- Q: IEEE 802.11은? — 무선 LAN (Wi-Fi, CSMA/CA)
- Q: IEEE 802.15는? — WPAN (블루투스·지그비 등 개인 근거리 무선망)

## 주소 · 망 기술

- **NAT (Network Address Translation)** — 내부망의 사설 IP 주소를 외부와 통신할 때 공인 IP 주소로 바꿔 주는 기술. 공인 주소를 아끼고 내부 구조를 숨기는 것
- **애드혹 네트워크 (Ad-hoc Network)** — 기지국·AP 같은 고정 기반 시설 없이 이동 노드끼리 스스로 망을 꾸려 통신하는 무선망. 재난 현장·군사용에 쓰이는 것
- **서브넷 마스크 (Subnet Mask)** — IP 주소에서 네트워크 부분과 호스트 부분을 가르는 32비트 값. 네트워크 비트는 1, 호스트 비트는 0인 것
  - 예: /24 = 255.255.255.0
- Q: `192.168.10.0/24`를 같은 크기의 서브넷 4개로 나눌 때 서브넷 마스크와 서브넷당 쓸 수 있는 호스트 수는? — `/26` (255.255.255.192), 서브넷당 62개
  - 서브넷마다 주소 64개 중 네트워크 주소와 브로드캐스트 주소 2개는 호스트에 못 쓴다

> VPN은 보안 과목에서 다룬다

## 패킷 교환 방식

- **가상 회선 방식 (Virtual Circuit)** — 전송을 시작하기 전에 송수신 사이의 논리적 경로를 먼저 정하고, 모든 패킷이 그 경로를 따라 보낸 순서대로 도착하는 연결형 패킷 교환 방식
- **데이터그램 방식 (Datagram)** — 경로를 미리 정하지 않고 패킷마다 독립적으로 그때그때 경로를 골라 보내는 비연결형 패킷 교환 방식. 도착 순서가 뒤바뀔 수 있어 수신 측이 재조립한다

## 근거리 무선 통신

- **NFC (Near Field Communication)** — 13.56MHz 대역에서 10cm 안팎의 아주 가까운 거리로 기기끼리 데이터를 주고받는 비접촉 무선 통신. 결제·출입 인증에 쓰이는 것
- **RFID (Radio Frequency IDentification)** — 사물에 붙인 태그의 정보를 리더기가 전파로 비접촉 판독해 사물을 구별하는 기술. 물류·재고·출입 관리에 쓰이는 것
- **UWB (Ultra-WideBand)** — 아주 넓은 주파수 대역에 걸쳐 낮은 전력의 짧은 펄스를 보내는 근거리 무선 기술. 고속 전송과 센티미터 단위 위치 측정에 쓰이는 것
- **피코넷 (Piconet)** — 블루투스 등에서 마스터 1대와 최대 7대의 활성 슬레이브가 모여 이루는 작은 무선망
- **WPAN (Wireless Personal Area Network)** — 한 사람 주변 약 10m 범위의 기기들을 무선으로 잇는 망. IEEE 802.15로 표준화된 것
  - 블루투스·지그비·UWB
- **블루투스 (Bluetooth)** — 2.4GHz ISM 대역에서 주파수 도약 방식으로 휴대 기기를 근거리 무선 연결하는 기술. IEEE 802.15.1 기반인 것

## ATM

- **ATM (Asynchronous Transfer Mode)** — 모든 데이터를 53바이트(헤더 5 + 페이로드 48) 고정 길이 셀로 나눠 통계적으로 다중화해 보내는 고속 교환 방식
- **AAL (ATM Adaptation Layer)** — 상위 계층이 넘긴 데이터를 48바이트 셀 페이로드 단위로 분할·재조립해 셀 교환 계층과 이어 주는 계층. 서비스 유형별로 1·2·3/4·5형이 있는 것
