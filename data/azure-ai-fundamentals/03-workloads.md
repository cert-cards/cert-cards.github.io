# 영역 1 · AI 워크로드

## 워크로드 고르기

- **텍스트 분석 (Text analysis)** — 정해진 형식이 없는 글에서 언어, 핵심 구절, 개체, 감정 같은 정보를 읽어 내는 자연어 처리 작업
- **컴퓨터 비전 (Computer vision)** — 이미지나 영상을 해석해 그 안의 사물, 글자, 장면, 사람을 알아내는 AI 분야
- **정보 추출 (Information extraction)** — 문서, 이미지, 오디오, 비디오처럼 형식이 제각각인 콘텐츠에서 필요한 값만 골라 정해진 필드 구조의 데이터로 바꾸는 작업
  - Foundry에서는 Azure Content Understanding in Foundry Tools가 이 일을 맡는다
- Q: 신상품 소개 문구를 톤만 바꿔 여러 버전으로 새로 써 주는 앱 — 생성형 AI
- Q: 직원 요청을 받으면 사내 일정 시스템을 조회하고 회의실 예약까지 처리하는 AI — 에이전틱 AI (에이전트)
  - 답을 만드는 데서 그치지 않고 도구를 불러 실제 행동까지 한다
- Q: 생성형 AI 챗봇과 에이전틱 AI를 가르는 기준 — 도구를 써서 목표를 여러 단계로 나눠 직접 실행하는가
- Q: 수천 건의 상품 리뷰가 좋은 평인지 나쁜 평인지 집계할 때 — 텍스트 분석 (감정 분석)
- Q: 콜센터 통화를 사람이 받아 적지 않고 글로 남기는 기능 — 음성 인식 (speech to text)
- Q: 공장 카메라 화면에서 안전모를 쓰지 않은 작업자의 위치를 찾을 때 — 컴퓨터 비전 (물체 감지)
- Q: 공급업체마다 양식이 다른 송장에서 업체명과 총액을 정해진 필드로 모을 때 — 정보 추출
- Q: 음성 메시지에서 발신자 이름, 회신 번호, 요청 사항을 필드별로 정리할 때 — 정보 추출 (오디오)
- Q: 텍스트 분석과 정보 추출의 차이 — 텍스트 분석은 감정, 개체 같은 정해진 분석을 글에 적용하고, 정보 추출은 내가 정한 필드 구조로 여러 형식의 콘텐츠에서 값을 뽑는다

## 텍스트 분석 기법

- **핵심 구절 추출 (Key phrase extraction)** — 글의 주요 개념을 이루는 낱말이나 짧은 구를 목록으로 돌려주는 기능. 문서 색인과 검색에 쓴다
  - 시험 범위에서는 keyword extraction이라고도 부른다
- **개체명 인식 (Named entity recognition)** — 글 속의 사람, 장소, 조직, 날짜, 수량 같은 항목을 찾아 미리 정한 범주와 하위 범주로 나누는 기능. NER로 줄여 쓴다
- **개체 연결 (Entity linking)** — 글에 나온 이름이 실제로 무엇을 가리키는지 문맥으로 가려내고 Wikipedia 같은 지식 베이스 링크를 붙여 주는 기능
  - 예: 같은 'Mars'가 행성인지 로마 신화의 신인지 구분한다
- **PII 감지 (PII detection)** — 이름, 전화번호, 주소, 이메일처럼 특정인을 알아볼 수 있는 정보를 찾고, 원하면 그 부분을 가린 텍스트도 돌려주는 기능
  - 건강 정보(PHI)도 찾는다. 대화 기록과 PDF, Word 같은 문서도 대상이다
- **감정 분석 (Sentiment analysis)** — 문서 전체와 문장마다 긍정, 중립, 부정 레이블을 매기고 각 레이블의 신뢰도 점수(0~1)를 함께 주는 기능
  - 레이블은 신뢰도가 가장 높은 쪽으로 정해진다
- **의견 마이닝 (Opinion mining)** — 글 전체의 분위기가 아니라 음식, 배송처럼 제품이나 서비스의 특정 측면마다 어떤 평가가 붙었는지 짚어 내는 기능
  - aspect-based sentiment analysis라고도 한다. 감정 분석에 딸린 기능이다
- Q: "음식은 훌륭했지만 직원은 불친절했다"에서 음식과 직원에 대한 평가를 따로 알고 싶을 때 — 의견 마이닝
- Q: 리뷰 한 건이 전체적으로 긍정인지 부정인지만 알면 될 때 — 감정 분석
- **언어 감지 (Language detection)** — 글이 어느 언어로 쓰였는지 판별해 언어 이름, ISO 639-1 코드, 신뢰도 점수를 돌려주는 기능
- Q: 여러 나라 말로 들어오는 문의를 알맞은 처리 흐름으로 보내기 전 첫 단계로 쓰는 기능 — 언어 감지
- **추출 요약 (Extractive summarization)** — 원문에서 중요한 문장을 골라 그대로 가져오고, 문장마다 순위 점수와 위치 정보를 붙이는 방식
- **생성 요약 (Abstractive summarization)** — 원문 문장을 베끼지 않고 내용을 간추린 새 문장을 지어 만드는 방식
- Q: 요약문의 문장이 원문 문장과 글자 하나 다르지 않다면 어느 방식인가 — 추출 요약 (extractive)
- Q: 상담원과 고객의 대화를 고객 문제와 해결 내용으로 나눠 요약하는 기능 — 대화 요약의 issue/resolution 요약
- Q: 긴 회의를 주제별 장으로 나누고 장마다 제목을 붙이는 기능 — 대화 요약의 chapter title 요약
- Q: NER과 개체 연결의 차이 — NER은 범주를 붙이고, 개체 연결은 어느 대상인지 가려 지식 베이스 링크를 붙인다
- Q: 글에서 '김민수'를 찾아 Person으로 분류하는 것과 '*****'로 가리는 것 — 앞은 NER, 뒤는 PII 감지의 가리기(redaction)
- Q: 진료 기록에서 약 이름, 용량, 진단을 뽑고 그 사이 관계까지 찾을 때 — Text analytics for health
- Q: 사내 계약서의 조항 유형처럼 우리 회사만 쓰는 범주를 뽑도록 직접 학습시킬 때 — Custom NER

## 음성 인식과 음성 합성

- **음성 인식 (Speech recognition)** — 사람의 말소리를 받아 텍스트 같은 데이터로 바꾸는 기능. speech to text(STT)라고도 한다
- **음성 합성 (Speech synthesis)** — 텍스트를 사람 목소리 같은 오디오로 읽어 주는 기능. text to speech(TTS)라고도 한다
- Q: 소리를 음소로 바꾸는 모델과 음소를 낱말로 잇는 모델 — 음향 모델(acoustic model), 언어 모델(language model)
- Q: 음성 합성에 꼭 필요한 두 가지 입력 — 읽을 텍스트, 읽을 목소리(voice)
- Q: 전자책을 오디오북으로 만들거나 차량 길 안내를 말로 들려주는 기능 — 음성 합성
- Q: 발표처럼 지금 말하는 소리를 바로 글로 옮기는 것과 저장소에 쌓인 녹음 파일을 한꺼번에 처리하는 것 — 앞은 실시간 전사, 뒤는 배치 전사
  - 배치 전사는 비동기로 돌고, 작업이 언제 시작될지 보장되지 않는다(best-effort)
- **뉴럴 보이스 (Neural voice)** — 심층 학습 모델이 만들어 억양 같은 기존 합성의 어색함을 줄이고 사람 말처럼 자연스럽게 들리는 합성 목소리
- **SSML (Speech Synthesis Markup Language)** — 합성할 문장의 높낮이, 발음, 말 빠르기, 음량, 쉼을 세밀하게 조정하는 XML 기반 마크업
  - 한 문서에서 여러 목소리를 쓰거나 녹음된 효과음을 끼워 넣을 수도 있다
- Q: 제품명 발음을 바로잡고 문장 사이에 쉼을 넣어야 할 때 — SSML
- Q: 기본 모델이 공장 소음이나 업계 전문 용어 때문에 말을 잘 못 알아들을 때 — Custom speech (사용자 지정 음성 인식 모델)
- Q: 우리 브랜드만의 고유한 목소리로 안내 음성을 만들 때 — Custom voice
  - 제한된 액세스(Limited Access) 대상이다
- **음성 번역 (Speech translation)** — 말한 내용을 실시간으로 다른 언어의 텍스트나 말소리로 바꿔 주는 기능
- Q: 오디오 속 화자가 어떤 언어로 말하는지부터 알아내야 할 때 — 언어 식별 (language identification)
- Q: 텍스트 언어 감지와 음성 언어 식별의 차이 — 언어 감지는 Azure Language가 글을, 언어 식별은 Azure Speech가 오디오를 대상으로 한다
- Q: 외국어 학습자의 말을 듣고 정확도와 유창성을 평가해 주는 기능 — 발음 평가 (pronunciation assessment)

## 컴퓨터 비전과 이미지 생성

- **이미지 분류 (Image classification)** — 이미지 전체에 하나 이상의 레이블을 붙이는 작업. 그 대상이 이미지의 어디에 있는지는 알려 주지 않는다
- **물체 감지 (Object detection)** — 이미지 속 항목에 레이블을 붙이고 각 항목의 위치를 경계 상자(bounding box) 좌표로 함께 돌려주는 작업
- Q: 사진이 고양이 사진인지만 알면 될 때와 사진 속 고양이 세 마리가 어디 있는지 알아야 할 때 — 앞은 이미지 분류, 뒤는 물체 감지
- **OCR (Optical character recognition)** — 사진이나 스캔한 페이지 속 글자를 읽어 편집과 검색이 되는 디지털 텍스트로 바꾸는 기술
- Q: 도로 표지판 사진에 적힌 문구를 텍스트로 꺼낼 때 — OCR
- Q: 시각 장애인용 앱이 사진마다 내용을 설명하는 문장을 만들어야 할 때 — 이미지 캡션 생성 (image captioning)
- Q: 사진 보관함을 '실내', '자전거', '나무' 같은 낱말로 색인해 검색하게 할 때 — 이미지 태깅 (tagging)
- Q: 이미지 분석 모델과 이미지 생성 모델이 일하는 방향 — 분석은 이미지를 받아 텍스트를 내고, 생성은 텍스트 설명을 받아 이미지를 만든다
- **얼굴 감지 (Face detection)** — 이미지에서 사람 얼굴을 찾아 그 위치를 사각형 좌표로 돌려주는 작업. 다른 모든 얼굴 기능의 첫 단계다
- Q: 얼굴 감지와 얼굴 인식의 차이 — 감지는 얼굴이 어디 있는지만, 인식은 그 얼굴이 누구인지(검증, 식별)까지 판단한다
- **라이브니스 감지 (Liveness detection)** — 카메라 앞 얼굴이 실제로 그 자리에 있는 사람인지, 사진이나 녹화 영상이나 가면 같은 위조인지 가려내는 위조 방지 기능
  - 신청해서 승인받아야 쓸 수 있는 기능이다
- Q: Face 리소스를 만들 때 동의해야 하는 사용 제한 — 미국 경찰서가 쓰거나 미국 경찰서를 위해 쓰지 않는다
- Q: Microsoft가 감정, 성별 같은 얼굴 속성 추론을 퇴역시키거나 제한한 이유 — 잘못 쓰이면 고정관념, 차별, 부당한 서비스 거부로 이어질 수 있어서
